Object

JavaScript Objects

Fundamental for storing and organizing data. They are collections of key-value pairs

Keys are strings (or Symbols), and values can be any JavaScript data type.

Key Concepts

  • Key-Value Pairs: Objects store data as pairs of keys and values. Think of it like a dictionary.
  • Properties: The "keys" are often referred to as "properties" of the object.
  • Methods: When a property's value is a function, it's called a "method."
  • Dynamic Nature: You can add, modify, or delete properties and methods at runtime.

Object

  • An object is a dynamic collection of related data
    • a property is an association between a name (or key) and a value
    • a property's value can be a function, in which case the property is known as a method (more on this later)
    • properties can be added and deleted after object creation

Object (continued)

  • Only two primitive types can be property keys:
    • string
    • symbol (not covered in this course)
    • Other types are autoconverted to strings:
      • obj[1] === obj["1"]
      • obj[true] === obj["true"]
  • Seven primitive types (string, number, bigint, boolean, symbol, null and undefined) and everything else is an object
  • Arrays and functions are objects too

Objects as key-value pairs

  • Other names (in other programming languages):
    • map (Note: JavaScript also has a built-in object Map which is similar but still different)
    • hash table
    • record
    • struct
    • associative array
    • dictionary
    • dict

Immediately Invoked Function Expression (IIFE)

  • An IIFE runs immediately after being defined.
  • It is often used to create a local scope and avoid polluting the global namespace.
  • It enables the Module pattern, allowing private variables and public methods.
  • Example of IIFE:

(function sayHi() {
    console.log("..remember me?");
})(); // The () at the end immediately invokes the function

    • more optimized as an internal method
  • Thus, in almost all cases, the shorter syntax is preferred

Manipulating objects

Accessing properties

  • Two different methods of accessing properties
    • dot notation (obj.property)
    • bracket notation (obj["property"])
  • Bracket notation must be used:
    • if the property name:
      • includes a space or a hyphen
      • starts with a number
      • is a symbol
    • when using a variable to access a property
// dot notation
let name = person.firstName; // get or read property
person.lastName = 'Smith'; // set or modify property

// bracket notation
let age = person['age']; // get or read property
person['isMarried'] = true; // set or modify property

// bracket notation and using variable to access property
let prop1 = 'age';
let prop2 = 'isMarried';
let isMarried = person[prop2]; // get or read property
person[prop1] = 36; // set or modify property

Adding and deleting properties

// dot notation
person.numberOfChildren = 3; // add new property

// bracket notation
person['occupation'] = 'teacher'; // add new property

// deleting properties
delete person.numberOfChildren;
delete person['occupation'];

for..in Looping over objects

  • Iterate through all the properties in an object
    • no guarantee of the order in which the properties are accessed
  • In general, it is best not to add, modify, or remove properties from the object during iteration, other than the property currently being visited.
  • break and continue work just like inside any other loop

for..in (continued)

// Syntax
  for (let key in object) {
    // executes the body for each key among object properties
  }
  
// Example
  let user = {
    name: 'John',
    age: 30,
    isAdmin: true
  };
  
  for (let key in user) {
    console.log(key); // "name", "age", "isAdmin"
    console.log(user[key]); // "John", 30, true
    // modifying current property's value is also OK
    // DO NOT add, delete or modify other properties inside the loop
  }

for..in and inheritance

  • The for..in loop iterates over inherited properties too
  • Use obj.hasOwnProperty(key) to detect object's own non-inherited properties 
let animal = { eats: true };
let rabbit = { jumps: true };
Object.setPrototypeOf(rabbit, animal);

// Object.keys only returns own keys
console.log(Object.keys(rabbit)); // jumps

// for..in loops over both own and inherited keys
for (let prop in rabbit) {
  if (rabbit.hasOwnProperty(prop)) {
    console.log('Own:', prop);
  } else {
    console.log('Inherited:', prop);
  }
}

Function vs. class-based creation

  • Function constructor applies with functional style, inheritance trickier
  • Classes are provided since ES6 as a convenience for object-oriented developers; looks similar to traditional OOP at first glance
  • Unlike a traditional class, a JavaScript object:
    • can be modified dynamically, including adding or changing properties, methods, and even altering its inheritance.
    • uses behavior delegation to "ask" its prototype (or its prototype's prototype, and so on) for missing properties or methods.
    • enables differential inheritance, meaning an object inherits just-in-time—only when a property or method is not found within its own properties.

new operator and constructor functions

  • The regular object literal syntax {...} allows us to create one object. But often we need to create many similar objects, like multiple users or menu items and so on.
  • That can be done using constructor functions and the new operator.

Constructor functions

like regular functions, but by convention, they follow two key rules:

  1. they are named with an uppercase first letter (e.g., Person).
  2. they should be called only with the new operator, which ensures that a new object is created and this is correctly assigned to it.

Constructor function (example)

function User(name) {
  this.name = name;
  this.isAdmin = false;
}

let user = new User('Jack');

console.log(user.name); // "Jack"
console.log(user.isAdmin); // false

Constructor function (Summary)

  • Constructors are used to create reusable object templates.
    • Examples: new User("Ann"), new User("Alice")
    • More efficient than using literals each time.
  • By convention, constructor functions start with a capital letter to indicate they should be run with new.
  • Technically, any function that returns an object (except arrow functions) can be used as a constructor.

Copying objects and arrays

  • Sometimes, we need an actual copy of an object or array instead of just a reference to the original
  • Shallow copy
    • Object.assign() – for objects only
    • arr.slice() – for arrays only
    • Spread syntax (...) – works for both objects and arrays
  • Deep copy (cloning)
    • structuredClone() – supports both objects and arrays
    • JSON.parse(JSON.stringify(obj)) – works but loses functions and special object types.

Object.assign()

  • Copies all enumerable own properties from one or more source objects to a target object. It returns the modified target object.
  • Create shallow copies of objects
    • Nested objects and arrays still reference to the original
  • NOTE: Overwrites target object's properties if source has properties with same names.
    • usually a good idea to use empty target object 
// Syntax
  Object.assign(target, ...sources);

Object.assign() (continued)

const car = {
    brand: 'Honda',
    model: 'Accord',
    year: 1998
  };
  
  // reference to the same object
  let car2 = car;
  console.log(car === car2); // true
  
  // copy object to an (initially) empty target
  car2 = Object.assign({}, car);
  console.log(car === car2); // false
  // "car" and "car2" are now referencing different objects

structuredClone() for deep clones

  • can be used for both arrays and objects
const triangle = {
    p1: { x: 0, y: 3 },
    p2: { x: 1, y: 4 },
    p3: { x: 2, y: 5 }
  };
  
  // reference to the same object (also the nested objects)
  let triangle2 = triangle;
  console.log(triangle === triangle2); // true
  console.log(triangle.p1 === triangle2.p1); // true
  
  // deep clone triangle
  triangle2 = structuredClone(triangle);
  console.log(triangle === triangle2); // false
  console.log(triangle.p1 === triangle2.p1); // false

Classes

In object-oriented programming, a class is an extensible program-code-template for creating objects, providing initial values for state (member variables) and implementations of behavior (member functions or methods). - Wikipedia

Classes (continued)

  • We often need to create many objects of the same kind, like users, products, menu items, etc.
  • As we already know, constructor functions and new operator can help with that.
  • In the modern JavaScript, there's a more advanced class construct, that introduces new features which are useful for object-oriented programming.

Classes (continued)

  • A class wraps up properties and methods
    • a class can be thought as a template
  • Enables easy instantiation of multiple objects from the same class
    • objects have same properties with different values
    • methods may change the values
  • Constructor gets automatically called with a new operator

class syntax

// Defining a class

  // class methods
  constructor() { ... }
  method1() { ... }
  method2() { ... }
  method3() { ... }
  ...

NOTE

  • No comma between class methods
  • class declarations are NOT hoisted
    • you cannot use a class before it is declared

extends and inheritance

  • New class (subclass) can be defined based on an existing class
    • subclass “borrows” large part of parent class's behaviour
    • subclass can add new behaviour and modify existing behaviour
  • The extends keyword is used in class declarations or class expressions to create subclasses

extends (continued)

  • Constructor of subclass must call parent class's constructor
    • must be called as the first thing in the child class's constructor'
    • call to super() should also pass the arguments needed by the parent's constructor

extends (example)

class Person {
  constructor(first, last) {
    this.firstName = first;
    this.lastName = last;
  }
}

class Teacher extends Person {
  constructor(first, last, subject, qualification) {
    super(first, last); // call parent class's constructor
    // subject and qualification
    this.subject = subject;
    this.qualification = qualification;
  }
}

subclass (example)

const indy = new Teacher('Indiana', 'Jones', 'archeology', 'professor');

// accessing properties of the parent and subclass
// both look identical from the outside

console.log(indy.subject); // "archeology"

// modifying properties also looks identical from the outside
indy.firstName = 'Indy';
console.log(indy.firstName); // "Indy"

Data hiding

Data hiding - getters and setters

  • To prevent the data from being corrupted (intentionally or accidentally)
  • To allow only dedicated methods to change the values of properties
    • by providing access to a property via get and set accessor methods
  • The underscore (_name) is a convention to denote a private property

getters and setters (example)

class User {
  constructor(name) {
    this.name = name; // invokes the setter
  }

  get name() {
    // underscore used to "_" denote private property
    return this._name;
  }

  set name(value) {
    // underscore used to "_" denote private property
    this._name = value;
  }
}

Getters and setters to access the data

get name() {
  return this._name;
}
  • outside the class, it still looks like name is the property
  • inside the class, it is implemented as a get accessor method 
set name(value) {
  this._name = value;
}
  • outside the class, it still looks like name is the property
  • inside the class, it is implemented as a set accessor method 
// Example usage
let user = new User('John');
console.log(user.name); // "John" (getter used)
user.name = 'Jack'; // (setter used)

getters and setters (another example)

// Hotel class with computed value
class Hotel {
  constructor(name, address, rooms) {
    this.name = name;
    this._address = address;
    this._rooms = rooms;
    this._bookings = 0;
  }
  get numberOfAvailableRooms() {
    return this._rooms - this._bookings;
  }
  get address() {
    return this._address;
  }
}

Computed values with getters

  • getters can also compute values
    • numberOfAvailableRooms is not actually a property, but is used like one outside the class
    • inside the class, it is implemented as a get method 
get numberOfAvailableRooms() {
  return this._rooms - this._bookings;
}

// Using computed value
const fineHotel = new Hotel('Hilton', 'Main Street 1', 15);
let available = fineHotel.numberOfAvailableRooms; // 15

Read-only properties with getters

  • Creating read-only properties is easy
    • Disguise the address property by providing no setter 
// setting address is prevented since there is no setter
const fineHotel = new Hotel('Hilton', 'Main Street 1', 15);
console.log(fineHotel.address); // (OK, using getter)
fineHotel.address = 'Country Road 10'; // (no setter)
console.log(fineHotel.address); // "Main Street 1" (remains unchanged, using getter)

The problem with underscore (“_”)

  • Why do we need the underscore (“_”) naming convention for data hiding?
    • Historically objects's did not have any means of hiding properties
    • A naming convention was developed to clearly mark private properties
    • The property is still publicly accessible and modifiable 
// NOTE: This is still allowed
const fineHotel = new Hotel('Hilton', 'Main Street 1', 15);
// (using _address directly and bypassing setter)
fineHotel._address = 'Back Alley';
console.log(fineHotel.address); // "Back Alley" (value changed)

Private class fields

  • Encapsulation in object-oriented programming
    • No direct access to the underlying implementation
    • Use well-abstracted interface (methods) to interact with the object
  • Naming convention is not sufficient
    • External code can access properties directly
    • Changes to the class internals potentially break code using the class

Private class fields (continued)

  • Classes provide truly private fields
    • Only accessible inside the class's own code
    • Safe to refactor class as long as the behaviour of public methods remains unchanged
  • Accessing private fields outside the class is a syntax error
    • Prevents anyone from depending on the internal implementation details of the class

Private class fields (example)

class User {
  #name; // Declare private field

  construct(name) {
    this.#name = name;
  }

  get name() {
    return this.#name;
  }

  sayHello() {
    console.log('Hello! My name is', this.#name);
  }
}

Private class fields (example, continued)

  • Now the user's name is truly a private property of the object
  • Modifying name after object creation is not possible since there is no set method for name 
const user = new User('John');
console.log(user.name); // "John"
console.log(user.#name); // SyntaxError
// (cannot access private property outside the class)

user.#name = 'Jack'; // SyntaxError
// (cannot set private property outside the class)

user.name = 'Jack'; // ERROR (no setter for name)

Private class fields (default values)

class Counter {
  #value = 0; // Private field with a default value 0

  reset() {
    this.#value = 0;
  }

  increment() {
    this.#value++;
  }

  get value() {
    return this.#value;
  }
}
  • Every new Counter object has #value set to 0
    • no other initializing necessary
    • constructor() not needed

Private class fields (default values)

// Counter example
const counter1 = new Counter();
const counter2 = new Counter();

// Both counters start with value 0
console.log(counter1.value); // 0
console.log(counter2.value); // 0

// Incrementing counter1 does not change counter2
// Both counter1 and counter2 have their own separate values
counter1.increment();
console.log(counter1.value); // 1
console.log(counter2.value); // 0

Private class fields (summary)

  • Protection for users, so that they don't shoot themselves in the foot
    • accidental modification of properties is prevented
  • Supportable classes
    • Internal properties and methods can change, even without informing the users as long as the behaviour doesn't change
  • Hiding complexity
    • Implementation details are hidden, and a simple, well-documented external interface is available.

  • Syntax for public class fields is similar to private fields
    • no # in the name

}

const user = new User('John');
user.name = 'James'; // no need for a setter (name is public)
console.log(user.name); // "James" (value changed, no getter)

Prototypes

Prototypal Inheritance

  • Why can we use built-in methods like .length, .split(), and .join() on e.g. strings and arrays?
    • these methods are not stored directly on individual values
    • but inherited from a shared prototype object
  • Unlike statically typed languages like Java or C++, JavaScript does not require predefined class structures. Objects can dynamically inherit properties and methods from other objects:
    • every object has an internal link to another object, known as its prototype
    • for example, when you call "hello".toUpperCase(), JavaScript first looks for toUpperCase() on the string itself
    • since primitive strings don's store methods, JavaScript follows the prototype chain and finds toUpperCase() on String.prototype
    • this delegation mechanism allows objects to "borrow" shared functionality instead of duplicating methods for each instance

Prototypal inheritance (continued)

  • Prototypal inheritance can be more powerful than the "classic" inheritances
    • JavaScript's classes are implemented on top of a prototypical model
  • While classes abstract most of the prototypical mechanism away, understanding how prototypes work under the hood is still useful

Prototype chain

  • each object has a private property which holds a link to another object called its prototype
    • prototype object can have a prototype of its own, and so on until an object is reached with null as its prototype
    • null acts as the final link in the prototype chain
    • any member of the prototype chain can be mutated or even swapped out at runtime
      • concepts like static dispatching do not exist in JavaScript

Prototype chain (continued)

  • JavaScript objects are dynamic collections of properties (referred to as own properties)
  • When trying to access a property of an object, and it's missing
    • the property will be sought on the prototype chain until either a property with a matching name is found or the end of the prototype chain is reached
  • The power of prototypes is that we can reuse a set of properties if they should be present on every instance

[[Prototype]] property

    • either null or
    • references another object which is called a prototype
    • "parent" of current object
  • [[Prototype]] is internal and hidden, so called internal slot, but can be set with:
    • constructor functions
    • classes and extends
    • Object.create()
    • Object.setPrototypeOf()
    • __proto__ setter (not recommended)

Object.setPrototypeOf()

  • All methods above will set the prototype chain at object creation time
  • Object.setPrototypeOf() allows mutating the [[Prototype]] internal property of an existing object 
const obj = { a: 1 };
  const anotherObj = { b: 2 };
  Object.setPrototypeOf(obj, anotherObj);
  // obj ---> anotherObj ---> Object.prototype ---> null

Object.setPrototypeOf() (continued)

  • To build longer prototype chains, we can set the [[Prototype]] of Constructor.prototype via the Object.setPrototypeOf() function 
function Base() {}
  function Derived() {}
  // Set the `[[Prototype]]` of `Derived.prototype`
  // to `Base.prototype`
  Object.setPrototypeOf(Derived.prototype, Base.prototype);
  
  const obj = new Derived();
  // obj --> Derived.prototype --> Base.prototype
  //     --> Object.prototype --> null

Object.setPrototypeOf() (continued)

  • the previous example is equivalent to using class and the extends syntax 
class Base {}
  class Derived extends Base {}
  
  const obj = new Derived();
  // obj --> Derived.prototype --> Base.prototype
  //     --> Object.prototype --> null

            func.call() and func.apply() example

  console.log(this.name + 'from' + city + ', ' + state);
