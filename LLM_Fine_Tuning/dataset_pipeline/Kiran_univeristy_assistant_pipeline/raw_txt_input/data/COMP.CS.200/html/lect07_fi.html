Gridin responsiivisuus uusien mahdollistajien avulla

  • fr edistää responsiivisuutta, Varautan tilaa, mikä on, enkä valu yli kuten prosenttiosuudet
  • On kolme muutakin responsiivisuutta parantavaa vaihetta:
    1. repeat()
    2. minmax()
    3. auto-fill / auto-fit

1. repeat()

  • Sarakkeiden leveydet voidaan määritellä seuraavasti:
  • grid-template-columns: 1fr 1fr 1fr 250px;
  • 1fr toisto voidaan poistaa seuraavasti:
  • repeat(3, 1fr)

Kertoja

Ensimmäinen parametri on kertoja, tässä tapauksessa sarakkeiden lukumäärä

Koko

Toinen parametri kertoo kunkin sarakkeen koon

Yhteensä:

grid-template-columns: repeat(3, 1fr) 250px;

2. repeat: koko nimellä minmax()

  • Koko voidaan tehdä vielä joustavammaksi
  • minmax() määrittelee alueen
    • Voi olla sekoitus absoluuttisia ja murtoarvoja, esim.
      • minmax(100px, 1fr)
  • Yhteenvetona:
grid-template-columns: repeat(3, minmax(100px, 1fr)) 250px;

minmax-logiikka:

  • minmax() yrittää taata riittävän tilan sisällölle
  • 1fr < 100px, silloin leveys on vähimmäisleveys: 100px;
  • 1fr > 100px, silloin se on 1fr

Viimeinen osa (250px) lisää "joustavuuspuskuria". Se ottaa mitä jää jäljelle 3 * minmax():sta, jos tila < laskettu leveys.

3. auto-fill/auto-fit

  • Tilanteessa, jossa tila loppuu kesken, elementit alkavat ylitäyttää raja-alueensa
    • Pahimmassa tapauksessa ne eivät ole enää näkyvissä
  • Jotta ruudukko olisi todella responsiivinen, myös kertoluvun on oltava "joustava"
  • auto-fill/auto-fit siirtävät päätöksen selaimelle
grid-template-columns: repeat(auto-fill, minmax(100px, 1fr)) 250px;
vs. 
grid-template-columns: repeat(auto-fit, minmax(100px, 1fr)) 250px;

Tilanteessa, jossa on liikaa tilaa: auto-fill vs. auto-fit

  • Jos tilaa on ylimäärin ja käytössä on minmax(100px, 1fr)

    • auto-fill: minimiarvo 100px käytetään,

    auto-fit: maksimiarvo 1fr käytetään sen sijaan.

Muistisääntö responsiivisuudesta

Media-kyselyt

Media-kyselyt

  • mahdollistavat responsiivisen suunnittelun ja paljon muuta...
  • tukevat esim. osoitintyyppejä, resoluutioita, kuvasuhteita
  • sopeutuminen näytön ominaisuuksiin ja käyttäjän mieltymyksiin voidaan toteuttaa hienojakoisesti
  • tällä kurssilla flex/grid ovat ensisijaisia keinoja responsiivisten suunnitelmien toteuttamiseksi, ja media-kyselyt toimivat vain täydentävänä tekniikkana

@media CSS:ssä

  • @media kuuluu ns. at-sääntöihin (muita sääntöjä ovat esim. @import, @property, @supports, ...)
  • @media-säännön sisällä määritellään media-kysely, joka kertoo, milloin seuraavat tyylit tulisi ottaa käyttöön.
  • media-kyselyt kirjoitetaan sulkeisiin ()

Media-kyselyiden vaihtoehdot

  1. media-ominaisuudet tarkistavat laitteen ominaisuuksia, kuten näytön kokoa (min-width: 900px), resoluutiota (resolution: 720dpi) tai orientaatiota (orientation: landscape)
  2. media-tyypit määrittävät kohdelaitteen tai ympäristön, kuten screen (pöytäkoneet ja kannettavat), print (tulostus), speech (ruudunlukijat) tai yleinen all.
  3. yhdistelmät loogisilla operaattoreilla kuten and, or (pilkku), not tai only, joilla voidaan luoda monimutkaisempia ehtoja

Media-kysely: media-ominaisuudet

width | min-width | max-width | height | min-height | max-height | aspect-ratio | color | resolution | orientation | scan ... 
@media (min-width: 768px)  { css-rule }
@media (min-width: 768px)  and (max-width: 991px) { css-rule }

Media-kysely: media-tyyppi

all | aural | braille | handheld | print | projection | screen | tty | tv | embossed | speech ... 
@media (print)  { css-rule }
@media (min-width: 700px), handheld and (orientation: landscape){  css-rule  }

Lisätietoa: W3Schools-materiaali

Tyypillinen media-kysely

  • Perustyylisäännöt ja erityiset tyylisäännöt tietyille näytön leveysalueille.
    • Ensiksi määritellään säännöt, jotka pätevät kaikilla ikkunoiden leveyksillä.
    • Media-kyselyillä voidaan muuttaa perussääntöjä tai lisätä uusia sääntöjä tietyille tilanteille.
p { 
                color: blue; 
                }
                /* Muista, ettei leveydet mene päällekkäin!*/
                @media (min-width: 1200px)  { 
                    säännöt leveille näytöille
                }
                @media (min-width: 992px) and (max-width: 1199px)  { 
                    säännöt kannettaville tietokoneille
                }

Sama media-kyselyillä

                /* Pienet laitteet (puhelimet, 600px ja pienemmät) */
                @media only screen and (max-width: 600px) {...}
                
                /* Pienet laitteet (pysty-tabletit ja isot puhelimet, 600px ja suuremmat) */
                @media only screen and (min-width: 600px) {...}
                
                /* Keskikokoiset laitteet (vaaka-tabletit, 768px ja suuremmat) */
                @media only screen and (min-width: 768px) {...}
                
                /* Suuret laitteet (kannettavat/pöytäkoneet, 992px ja suuremmat) */
                @media only screen and (min-width: 992px) {...}
                
                /* Erittäin suuret laitteet (suuret kannettavat ja pöytäkoneet, 1200px ja suuremmat) */
                @media only screen and (min-width: 1200px) {...}

Nämä viisi tyypillistä laitekokoaluejakoa on W3Schoolissa esitelty de facto -standardina.

Bootstrap (getbootstrap.com)

Tehokas, laajennettava ja ominaisuusrikas frontend-työkalupakki. Hyödynnä valmiiksi rakennettua ruudukkosysteemiä ja komponentteja sekä tuo projektit eloon tehokkailla JavaScript-lisäosilla.
  • Bootstrap on suosittu avoimen lähdekoodin front-end-kehityskehys

  • ruudukolla on kuusi responsiivista katkaisukohtaa, jotka ovat 12:n kerrannaisia

Bootstrap ja saavutettavuus

  • Bootstrap tukee sisäänrakennettuna useita ARIA-attribuutteja saavutettavuuden parantamiseksi
    • aria-label: tarjoaa nimen elementille, jolla ei ole näkyvää otsikkoa. Auttaa apuvälineitä, kuten ruudunlukijoita, antamaan lisätietoa komponenteille kuten painikkeille, navigoinnille ja lomakkeille.
    • aria-describedby: antaa lisäkuvauksen elementille ja auttaa käyttäjiä ymmärtämään sen tarkoituksen.
    • aria-expanded: ilmaisee, onko elementti laajennettu vai supistettu.
    • aria-haspopup: ilmaisee, sisältääkö elementti ponnahdusikkunan tai valikon.
    • aria-hidden: piilottaa elementin apuvälineiltä, kuten ruudunlukijoilta.
  • Näiden ARIA-attribuuttien avulla Bootstrap varmistaa, että sen komponentit ovat saavutettavia kaikille käyttäjille, mukaan lukien vammaisille käyttäjille.

Tasa-arvoiset mahdollisuudet

  • tasavertainen mahdollisuus tiedon saantiin kaikille

W3C-aloitteet

  • Useat spesifikaatiot ja projektit tähtäävät parempaan saavutettavuuteen
    1. Verkkosisällön saavutettavuusohjeet (WCAG)
    2. WAI-ARIA (W3C)
    3. https://a11yproject.com/ tarjoaa joukkoistettuja saavutettavuusartikkeleita ja tietoa
A11y on lyhennetty tapa kirjoittaa saavutettavuus (accessibility). Se on "numeronyymi", jossa 11 tarkoittaa 11 puuttuvaa kirjainta 'a':n ja 'y':n välillä.

HTML Saavutettavuus

  • kirjoita HTML saavutettavuus huomioiden
  • tarjoa käyttäjälle hyvä tapa navigoida ja käyttää sivustoasi: tärkeimpien asioiden tulee olla helposti saatavilla
  • tee HTML-koodistasi mahdollisimman semanttinen, jotta se on helposti ymmärrettävä sekä kävijöille että ruudunlukijoille
  • Muista, että väärä ARIA on huonompi kuin ei ARIAa ollenkaan - paljon voi saavuttaa jo semanttisilla tageilla
