Olio

JavaScript-oliot

Olioita käytetään tiedon tallentamiseen ja järjestämiseen. Ne ovat avain-arvo -pareista koostuvia kokoelmia.

Avaimet ovat merkkijonoja (tai symboleja), ja arvot voivat olla mitä tahansa JavaScriptin tietotyyppejä.

Keskeiset käsitteet

  • Avain-arvo -parit: Olioihin tallennetaan tietoa avain-arvo -pareina. Vastaavat sanakirjoja.
  • Ominaisuudet: Avain tunnetaan myös nimellä "ominaisuus".
  • Metodit: Jos ominaisuuden arvo on funktio, sitä kutsutaan metodiksi.
  • Dynaamisuus: Ominaisuuksia ja metodeja voi lisätä, muokata ja poistaa ajon aikana.

Olio

  • Olio on dynaaminen kokoelma liittyvää dataa
    • ominaisuus on yhteys nimen (tai avaimen) ja arvon välillä
    • jos ominaisuuden arvo on funktio, sitä kutsutaan metodiksi (lisää tästä myöhemmin)
    • ominaisuuksia voi lisätä ja poistaa olion luomisen jälkeen

Olio (jatkuu)

  • Vain kaksi primitiivityyppiä voi toimia ominaisuuden avaimina:
    • string
    • symbol (ei käsitellä tässä kurssissa)
    • Muut tyypit muunnetaan automaattisesti merkkijonoiksi:
      • obj[1] === obj["1"]
      • obj[true] === obj["true"]
  • Seitsemän primitiivityyppiä (string, number, bigint, boolean, symbol, null ja undefined) – kaikki muu on olioita
  • Taulukot ja funktiot ovat myös olioita

Oliot avain-arvo -pareina

  • Muita nimiä muissa ohjelmointikielissä:
    • map (JavaScriptissä on myös erillinen Map-olio, joka on samankaltainen mutta eri)
    • hash-taulu
    • tietue
    • rakenne
    • assosiatiivinen taulukko
    • sanakirja
    • dict

Esimerkki: Yksinkertainen olio

const person = {
        firstName: "Alice",
        lastName: "Smith",
        age: 30,
        greet: function() {
          console.log(`Hei, nimeni on ${this.firstName} ${this.lastName}`);
        }
      };
      
      console.log(person.firstName); // Tulostaa: Alice
      person.greet(); // Tulostaa: Hei, nimeni on Alice Smith

Esimerkissä olio luotiin oliolitteraalilla. Oliot auttavat jäsentämään monimutkaista dataa JavaScriptissä.

Taulukko vs. Olio (assosiatiivinen taulukko)

  • Taulukko: Indeksoidaan numeroilla (0 .. N)
    • const myArr = ['punainen', 'sininen', 'keltainen', 'violetti'];
  • Visuaalinen esitys:
Avaimen Arvo
0 'punainen'
1 'sininen'
2 'keltainen'
3 'violetti'

Metodit olioissa

Metodi: lambda ominaisuuden arvona

  • Olioiden käyttäytyminen (metodit) luodaan funktioiden avulla
const person = {
firstName: "Mickey",
lastName: "Mouse",
isFiction: true,
numberOfFriends: 63,
fullName: function() {
    return this.firstName + " " + this.lastName;
}
};

const p1 = person.fullName();

Funktio-ilmaisu kutsuttuna () kanssa

  • Ilman sulkeita funktion viittaus tallennetaan arvona
let p2 = person.fullName;
console.log("p2 = " + p2);

// Tulostaa: function (){ return this.firstName + " " + this.lastName; }

// Kutsutaan () kanssa, oikein!
p2 = person.fullName();
// Tämä ei kuitenkaan toimi, miksi?
const name = p2();

Välittömästi kutsuttava funktioilmaisu (IIFE)

  • IIFE suoritetaan välittömästi sen määrittelyn jälkeen.
  • Sitä käytetään usein paikallisen alueen (scope) luomiseen ja globaalin nimitilan saastuttamisen estämiseen.
  • Mahdollistaa moduulimallin, mikä sallii yksityiset muuttujat ja julkiset metodit.
  • Esimerkki IIFE:stä:

(function sayHi() {
    console.log("..muista minut?");
})(); // Sulkeet lopussa kutsuvat funktion heti

Metodiesimerkkejä

  • Opetetaan ensin secretAgent sanomaan "Hello" 
const secretAgent = {
  firstName: 'James',
  lastName: 'Bond'
};

secretAgent.sayHello = function () {
  console.log('Hello');
};

secretAgent.sayHello(); // "Hello"

Metodiesimerkkejä (jatkuu)

  • Tässä käytämme funktioilmaisua luodaksemme funktion ja määritämme sen ominaisuudeksi secretAgent.sayHello oliossa.
  • Sen jälkeen voimme kutsua sitä kuten secretAgent.sayHello(). Nyt secretAgent osaa puhua!
  • Funktio, joka on olion ominaisuus, on sen metodi.
  • Tässä tapauksessa meillä on metodi sayHello, joka kuuluu oliolle secretAgent.

Metodiesimerkkejä (jatkuu)

  • Ennalta määritellyn funktion lisääminen olioon metodina 
    • const salainenAgentti = {
              // ...
            };
            
            // ensin, määritellään funktio
            function sanoHei() {
              console.log('Hei');
            }
            
            // sitten lisätään se metodiksi
            salainenAgentti.sanoHei = sanoHei;
            
            salainenAgentti.sanoHei(); // "Hei"

Metodien lyhennetty syntaksi

  • Lyhyempi tapa määritellä metodeja olioissa:
const salainenAgentti = {
  etunimi: 'James',
  sukunimi: 'Bond',
  sanoHei: function () {
    console.log('Hei');
  }
};

// metodien lyhennetty syntaksi
const salainenAgentti = {
  etunimi: 'James',
  sukunimi: 'Bond',
  sanoHei() {         
    console.log('Hei'); 
  } //suositeltava tapa!
};

Metodien lyhennetty syntaksi (jatkuu)

  • Voimme jättää function-avainsanan pois ja käyttää vain sanoHei().
  • Notaatioilla on pieniä eroja, jotka liittyvät periytymiseen:
    • Lyhennetty versio mahdollistaa super-kutsut
    • Paremmin optimoitu sisäinen metodi
  • Siksi lähes kaikissa tapauksissa lyhyempi syntaksi on parempi

Olioiden käsittely

Ominaisuuksiin pääsy

  • Kaksi tapaa käyttää ominaisuuksia
    • Pistenotaatiolla (obj.ominaisuus)
    • Hakasulkunotaatiolla (obj["ominaisuus"])
  • Hakasulkunotaatiota on käytettävä, jos ominaisuuden nimi:
    • sisältää välilyönnin tai yhdysmerkin
    • alkaa numerolla
    • on symboli
  • Kun käytetään muuttujaa ominaisuuden haussa
// pistenotaatio
let nimi = henkilo.etunimi; // haetaan ominaisuus
henkilo.sukunimi = 'Virtanen'; // asetetaan ominaisuus

// hakasulkunotaatio
let ika = henkilo['ika']; // haetaan ominaisuus
henkilo['naimisissa'] = true; // asetetaan ominaisuus

// hakasulkunotaatio muuttujan kanssa
let ominaisuus1 = 'ika';
let ominaisuus2 = 'naimisissa';
let naimisissa = henkilo[ominaisuus2]; // haetaan ominaisuus
henkilo[ominaisuus1] = 36; // asetetaan ominaisuus

Ominaisuuksien lisääminen ja poistaminen

// pistenotaatio
henkilo.lastenlkm = 3; // uusi ominaisuus

// hakasulkunotaatio
henkilo['ammatti'] = 'opettaja'; // uusi ominaisuus

// ominaisuuden poistaminen
delete henkilo.lastenlkm;
delete henkilo['ammatti'];

Luonti

Erilaisia tapoja luoda olioita

  1. olio-literal
  2. JSON-jäsennys
  3. funktiokonstruktori
  4. kopiointi
  5. luokat (käsitellään tarkemmin myöhemmissä luvuissa)
  6. Object.create()

Funktio- vs. luokkapohjainen luonti

  • Funktiokonstruktori soveltuu funktionaaliseen tyyliin, mutta periytyminen on hankalampaa
  • Luokat ovat saatavilla ES6:sta lähtien helpottamaan oliopohjaista ohjelmointia; näyttää ensi silmäyksellä perinteiseltä OOP:lta
  • JavaScript-olio eroaa perinteisestä luokasta:
    • voi muuttua dynaamisesti, eli ominaisuuksia ja metodeja voi lisätä tai muuttaa, ja jopa periytymistä voi muokata
    • käyttää käyttäytymisen delegointia kysyäkseen prototyypiltään (tai sen prototyypin prototyypiltä jne.) puuttuvia ominaisuuksia tai metodeja
    • mahdollistaa differenssiperiytymisen, eli olio perii ominaisuuksia vasta tarvittaessa, jos niitä ei löydy omista ominaisuuksista

Olioiden luonti (literal notation)

  • Koostuu ominaisuuksista pilkulla eroteltuina nimi-arvo-pareina
  • Olio luodaan {}-suilla, kun taas taulukot käyttävät []-sulkuja
const myObject = {
  firstName: "Elon",
  lastName: "Musk",
  isFiction: false
};
Nimi Arvo
firstName "Elon"
lastName "Musk"
isFiction false

Sisäkkäiset oliot literal notation -merkinnällä

  • Olio voi sisältää muita olioita ominaisuuksina
  • Sisäkkäinen notaatiotapa on mahdollinen pilkkuerottelulla
const kolmio = {
p1: { x: 0, y: 3 },
p2: { x: 1, y: 4 },
p3: { x: 2, y: 5 }
};
console.log(kolmio.p1.y); // tulostaa 3

kolmio-olio koostuu kolmesta pisteestä, jotka määritellään (x,y)-koordinaateilla.

Ovatko p1-p3 omia olioitaan? Miten kopioida?

Konstruktori-funktiot

Ne ovat tavallisia funktioita, mutta noudattavat kahta pääsääntöä:

  1. Niiden nimi alkaa isolla kirjaimella (esim. Henkilö).
  2. Ne tulisi kutsua vain new-operaattorin avulla, jotta uusi olio luodaan ja this osoittaa siihen oikein.

Konstruktori-funktio (esimerkki)

function Kayttaja(nimi) {
  this.nimi = nimi;
  this.onYllapitaja = false;
}

let kayttaja = new Kayttaja('Matti');

console.log(kayttaja.nimi); // "Matti"
console.log(kayttaja.onYllapitaja); // false

Luokat

Oliopohjaisessa ohjelmoinnissa luokka on laajennettava ohjelmakoodin malli, jonka avulla voidaan luoda olioita, määrittää niiden alkutila (jäsenmuuttujat) ja toteuttaa niiden käyttäytyminen (jäsenfunktiot tai -metodit). - Wikipedia

Luokat (jatkuu)

  • Usein tarvitsemme luoda useita samanlaisia olioita, kuten käyttäjiä, tuotteita, valikkokohteita jne.
  • Kuten tiedämme, rakentajafunktiot ja new-operaattori voivat auttaa tässä.
  • Modernissa JavaScriptissä on kehittyneempi class-rakenne, joka tuo uusia hyödyllisiä ominaisuuksia oliopohjaiseen ohjelmointiin.

Luokat (jatkuu)

  • class kokoaa ominaisuudet ja metodit yhteen
    • class voidaan ajatella mallina
  • Mahdollistaa useiden olioiden helpon luomisen samasta class-rakenteesta
    • oliot omaavat samat ominaisuudet eri arvoilla
    • metodit voivat muuttaa arvoja
  • Rakentajafunktio kutsutaan automaattisesti new-operaattorilla

class-syntaksi


      // Luokan määrittely
      class MyClass {
        // Luokan metodit
        constructor() { ... }
        method1() { ... }
        method2() { ... }
        method3() { ... }
        ...
      }

HUOM

  • Luokan metodien välissä ei ole pilkkua
  • Luokkadefinitiot eivät ole nostettuina (hoisted)
    • luokkaa ei voi käyttää ennen sen määrittelyä

Luokan määrittely (esimerkki)


      class User {
        constructor(name) {
          this.name = name;
        }
      
        sayHello() {
          console.log('Hei! Nimeni on', this.name);
        }
      }
      
      // Käyttö:
      let user = new User('John');
      user.sayHello(); // "Hei! Nimeni on John"
  • Kun new User("John") kutsutaan:
    1. Uusi olio luodaan.
    2. Rakentajafunktio suoritetaan annetulla parametrilla ja se tallennetaan this.name-muuttujaan.

Luokkailmaisu

  • Kuten funktiot, myös luokat voidaan määritellä toisessa ilmaisussa, välittää eteenpäin, palauttaa, määrittää muuttujaksi jne. 
// Esimerkki luokkailmaisusta
let User = class {
  sayHello() {
    console.log('Hei');
  }
};

extends ja periytyminen

  • Uusi class (alikategoria) voidaan määrittää aiemman class-rakenteen pohjalta
    • aliluokka "lainaa" suurimman osan vanhemman class-rakenteen toiminnoista
    • aliluokka voi lisätä uusia toimintoja ja muokata olemassa olevia
  • extends-avainsanaa käytetään class-määrittelyissä tai ilmaisemaan periytymistä

extends (jatkuu)

  • Aliluokan rakentajafunktion täytyy kutsua vanhemman class-rakentajaa
    • täytyy kutsua ensimmäisenä asiana aliluokan rakentajassa
    • kutsussa super() täytyy välittää parametrit, jotka vanhemman rakentaja tarvitsee

extends (esimerkki)

class Henkilo {
  constructor(etunimi, sukunimi) {
    this.etunimi = etunimi;
    this.sukunimi = sukunimi;
  }
}

class Opettaja extends Henkilo {
  constructor(etunimi, sukunimi, aine, patevyys) {
    super(etunimi, sukunimi);
    this.aine = aine;
    this.patevyys = patevyys;
  }
}

Tietojen piilottaminen

Tietojen piilottaminen - getterit ja setterit

  • Estetään tietojen korruptoituminen (tahallisesti tai vahingossa)
  • Varmistetaan, että vain tietyt metodit voivat muuttaa ominaisuuksien arvoja
    • tarjoamalla pääsy ominaisuuteen get- ja set-metodeilla
  • Alaviiva (_nimi) on konventio, joka merkitsee yksityistä ominaisuutta

Getterit ja setterit (esimerkki)

class User {
  constructor(name) {
    this.name = name; // kutsuu setteriä
  }

  get name() {
    return this._name;
  }

  set name(value) {
    this._name = value;
  }
}

Getterit ja setterit tietojen käsittelyyn

get name() {
  return this._name;
}
  • Luokan ulkopuolella name näyttää edelleen ominaisuudelta
  • Luokan sisällä se on toteutettu get-metodina 
set name(value) {
          this._name = value;
        }
  • Luokan ulkopuolella name näyttää edelleen ominaisuudelta
  • Luokan sisällä se on toteutettu set-metodina 
// Esimerkki käytöstä
let user = new User('John');
console.log(user.name); // "John" (getter käytössä)
user.name = 'Jack'; // (setter käytössä)

Getterit ja setterit (toinen esimerkki)

// Hotelli-luokka laskettavalla arvolla
class Hotel {
  constructor(name, address, rooms) {
    this.name = name;
    this._address = address;
    this._rooms = rooms;
    this._bookings = 0;
  }
  get numberOfAvailableRooms() {
    return this._rooms - this._bookings;
  }
  get address() {
    return this._address;
  }
}

Vain luku -ominaisuudet gettereillä

  • Vain luku -ominaisuuksien luominen on helppoa
    • Piilota osoite-ominaisuus jättämällä sille määrittelemättä setter-metodi 
// Osoitteen asettaminen estetty, koska setter puuttuu
const hotelli = new Hotelli('Hilton', 'Pääskyläntie 1', 15);
console.log(hotelli.osoite); // (OK, käyttää getteriä)
hotelli.osoite = 'Maalaistie 10'; // (ei setter-metodia)
console.log(hotelli.osoite); // "Pääskyläntie 1" (pysyy muuttumattomana, käyttää getteriä)

Ongelma alaviivan (“_”) kanssa

  • Miksi alaviivaa (“_”) käytetään tietojen piilottamiseen?
    • Alun perin olioilla ei ollut sisäänrakennettua tapaa piilottaa ominaisuuksia
    • Käyttöön otettiin nimeämiskäytäntö yksityisten ominaisuuksien merkitsemiseksi
    • Ominaisuus on silti julkisesti luettavissa ja muokattavissa 
// HUOM: Tämä on edelleen mahdollista
const hotelli = new Hotelli('Hilton', 'Pääskyläntie 1', 15);
// (käytetään _osoite suoraan, ohittaen getterin)
hotelli._osoite = 'Takakatu';
console.log(hotelli.osoite); // "Takakatu" (arvo muuttui)

Yksityiset luokkakentät

  • Inkarnaatio olio-ohjelmoinnissa
    • Ei suoraa pääsyä sisäiseen toteutukseen
    • Käytetään hyvin määriteltyjä rajapintoja (metodeja) olion käsittelyyn
  • Nimeämiskäytäntö ei riitä
    • Ulkopuolinen koodi voi yhä käyttää ominaisuuksia suoraan
    • Muutokset class-sisäiseen toteutukseen voivat rikkoa sitä käyttävää koodia

Yksityiset luokkakentät (esimerkki)

class Kayttaja {
  #nimi; // Määritellään yksityinen kenttä

  constructor(nimi) {
    this.#nimi = nimi;
  }

  get nimi() {
    return this.#nimi;
  }

  sanoHei() {
    console.log('Hei! Nimeni on', this.#nimi);
  }
}

Yksityiset luokkakentät (jatkuu)

  • Nyt käyttäjän nimi on todella yksityinen ominaisuus
  • Nimen muuttaminen olion luonnin jälkeen ei ole mahdollista, koska setter-metodia ei ole määritelty 
const kayttaja = new Kayttaja('Matti');
console.log(kayttaja.nimi); // "Matti"
console.log(kayttaja.#nimi); // SyntaxError
// (ei voi käyttää yksityistä ominaisuutta luokan ulkopuolella)

kayttaja.#nimi = 'Jussi'; // SyntaxError
// (ei voi muuttaa yksityistä ominaisuutta luokan ulkopuolella)

Yksityiset luokkakentät (oletusarvot)

class Counter {
  #value = 0; // Yksityinen kenttä, jonka oletusarvo on 0

  reset() {
    this.#value = 0;
  }

  increment() {
    this.#value++;
  }

  get value() {
    return this.#value;
  }
}
  • Jokaisella uudella Counter-oliolla on #value asetettuna 0
    • ei vaadi erillistä alustusta
    • constructor() ei ole tarpeen

Yksityiset luokkakentät (oletusarvot)

// Counter-esimerkki
const counter1 = new Counter();
const counter2 = new Counter();

// Molemmat laskurit alkavat arvosta 0
console.log(counter1.value); // 0
console.log(counter2.value); // 0

// counter1:n kasvattaminen ei muuta counter2:n arvoa
// Molemmilla on omat erilliset arvonsa
counter1.increment();
console.log(counter1.value); // 1
console.log(counter2.value); // 0

Yksityiset luokkakentät (yhteenveto)

  • Suojaa käyttäjiä, jotta he eivät vahingossa aiheuta ongelmia
    • estää ominaisuuksien tahattoman muuttamisen
  • Ylläpidettävät luokat
    • Sisäisiä ominaisuuksia ja metodeja voidaan muuttaa ilman, että käyttäjien tarvitsee tietää siitä, kunhan toiminta pysyy samana
  • Piilottaa monimutkaisuuden
    • Toteutuksen yksityiskohdat ovat piilossa, ja saatavilla on yksinkertainen, hyvin dokumentoitu ulkoinen rajapinta.

Julkiset luokkakentät

  • Yksityisillä kentillä on myös julkiset vastineensa
  • Julkisten luokkakenttien syntaksi on samanlainen kuin yksityisten kenttien
    • ei #-merkkiä nimen edessä
class User {
  name;

  constructor(name) {
    this.name = name;
  }
}

const user = new User('John');
user.name = 'James'; // setter ei ole tarpeen (name on julkinen)
console.log(user.name); // "James" (arvo muuttui, ei tarvetta getterille)

Prototyypit

Prototyyppinen periytyminen

  • Miksi voimme käyttää sisäänrakennettuja menetelmiä kuten .length, .split() ja .join() esimerkiksi merkkijonoissa ja taulukoissa?
    • nämä metodit eivät ole suoraan yksittäisissä arvoissa
    • vaan ne periytyvät yhteisestä prototyyppioliosta
  • Toisin kuin staattisesti tyypitetyissä kielissä kuten Java tai C++, JavaScript ei vaadi ennalta määriteltyjä luokkarakenteita. Oliot voivat dynaamisesti periä ominaisuuksia ja metodeja muilta olioilta:
    • jokaisella oliolla on sisäinen linkki toiseen olioon, jota kutsutaan sen prototyypiksi
    • esimerkiksi kun kutsut "hello".toUpperCase(), JavaScript etsii ensin toUpperCase() -metodia itse merkkijonosta
    • koska primitiiviset merkkijonot eivät tallenna metodeja, JavaScript seuraa prototyyppiketjua ja löytää toUpperCase() -metodin String.prototype-oliosta
    • tämä delegointimekanismi mahdollistaa sen, että oliot voivat "lainata" yhteisiä toimintoja ilman, että metodeja kopioidaan jokaiselle instanssille erikseen

Prototyyppinen periytyminen (jatkuu)

  • Prototyyppinen periytyminen voi olla tehokkaampi kuin "klassinen" periytyminen
    • JavaScriptin luokat on toteutettu prototyyppimallin päälle
  • Vaikka luokat piilottavat suurimman osan prototyyppimekanismista, on silti hyödyllistä ymmärtää, miten prototyypit toimivat pinnan alla

Prototyyppiketju

  • Ketju muodostuu, koska jokaisella oliolla on yksityinen ominaisuus, joka sisältää linkin toiseen olioon, jota kutsutaan sen prototyypiksi
    • Seuraava prototyyppiolio voi puolestaan sisältää oman prototyypin ja niin edelleen, kunnes saavutetaan olio, jonka prototyyppi on null
    • null toimii viimeisenä linkkinä prototyyppiketjussa
    • Mikä tahansa prototyyppiketjun jäsen voidaan muuttaa tai jopa vaihtaa ajonaikaisesti
      • Käsitteet kuten staattinen lähetys eivät ole olemassa JavaScriptissä

Prototyyppiketju (jatkuu)

  • JavaScript-oliot ovat dynaamisia ominaisuuskokoelmia (kutsutaan omia ominaisuuksia)
  • Kun yritetään käyttää olion ominaisuutta, ja sitä ei löydy
    • ominaisuutta etsitään prototyyppiketjusta, kunnes joko löytyy vastaava ominaisuus tai prototyyppiketjun loppu saavutetaan
  • Prototyyppien voima on siinä, että voimme uudelleenkäyttää ominaisuuksia, jotka pitäisi olla läsnä jokaisessa instanssissa

[[Prototype]]-ominaisuus

    • joko null tai
    • viittaa toiseen olioon, jota kutsutaan prototyypiksi
    • "vanhempi" nykyiselle oliolle
  • [[Prototype]] on sisäinen ja piilotettu, ns. internal slot, mutta sen voi asettaa:
    • konstruktori-funktioilla
    • luokilla ja extends-avainsanalla
    • Object.create()
    • Object.setPrototypeOf()
    • __proto__-asettajalla (ei suositella)

Object.setPrototypeOf()

  • Kaikki yllä mainitut menetelmät asettavat prototyyppiketjun olion luomishetkellä
  • Object.setPrototypeOf() mahdollistaa olemassa olevan olion [[Prototype]]-sisäisen ominaisuuden muuttamisen 
const obj = { a: 1 };
            const anotherObj = { b: 2 };
            Object.setPrototypeOf(obj, anotherObj);
            // obj ---> anotherObj ---> Object.prototype ---> null

Object.setPrototypeOf() (jatkuu)

  • Rakentaaksemme pidempiä prototyyppiketjuja voimme asettaa [[Prototype]]:n Constructor.prototype:lle käyttäen Object.setPrototypeOf()-funktiota 
function Base() {}
            function Derived() {}
            // Aseta `[[Prototype]]` kohteelle `Derived.prototype`
            // niin, että se osoittaa `Base.prototype`
            Object.setPrototypeOf(Derived.prototype, Base.prototype);
            
            const obj = new Derived();
            // obj --> Derived.prototype --> Base.prototype
            //     --> Object.prototype --> null

Object.setPrototypeOf() (jatkuu)

  • Edellinen esimerkki on sama kuin käyttämällä class-rakennetta ja extends-syntaksia 
class Base {}
            class Derived extends Base {}
            
            const obj = new Derived();
            // obj --> Derived.prototype --> Base.prototype
            //     --> Object.prototype --> null

this

        

        

          
this nykyisenä kontekstina

          
    
            
  • määrittää funktion suoritusympäristön, viitaten objektiin, joka kutsuu sen
    • 
            
  • mahdollistaa funktion uudelleenkäytön eri objekteissa sitomalla dynaamisesti this
    • 
            
  • toiminta riippuu siitä, miten funktio kutsutaan:
              
      
                
    • metodissa: this viittaa objektiin
      • 
                
    • tavallisessa funktiossa: this viittaa undefined:iin tiukassa tilassa
                  (strict mode) tai globaaliin objektiin muuten
      • 
                
    • new-operaattorilla: this viittaa juuri luotuun objektiin
      • 
                
    • eksplisiittinen sitominen: metodit kuten call(), apply() ja
                  bind() voivat asettaa this
      • 
                
    • nuolifunktiot: this perii arvonsa leksikaalisesti ympäröivästä kontekstista
      • 
              
    
            
    • 
          

        


        

          
this-avainsana eri konteksteissa

          
let student = {
  name: "Pasi",
  sayName: function() {
    console.log("Hei " + this.name);
  }
};

          
    
            
  • Metodissa this viittaa omistajaobjektiin.
    • 
            
  • Funktiona this viittaa globaaliin objektiin.
    • 
            
  • Tiukassa tilassa this on undefined funktion sisällä.
    • 
            
  • Tapahtumankäsittelijässä this viittaa elementtiin, joka vastaanottaa tapahtuman.
    • 
            
  • call(), bind() ja apply() voivat eksplisiittisesti asettaa
              this:n.
    • 
          

          
Lisätietoja: JavaScript this
          

        


        

          
this metodeissa

          
    
            
  • 
              Usein metodi tarvitsee käyttää olion itsensä tallentamaa tietoa suorittaakseen tehtävänsä.
            
    • 
            
  • 
              Esimerkiksi secretAgent.sayHello()-metodi saattaa tarvita agentin nimeä.
            
    • 
            
  • 
              Päästäkseen käsiksi olioon, metodi voi käyttää this-avainsanaa.
            
    • 
            
  • 
              this-avainsanan arvo on olio, joka on ennen pistettä, eli se, jota käytettiin metodin
              kutsuun.
            
    • 
          

        


        

          
this metodeissa (jatkuu)

          
    
            
  • 
              Esimerkiksi suoritettaessa secretAgent.sayHello(), this-arvona
              on secretAgent-olio itse.
            
    • 
          

          
const secretAgent = {
  firstName: 'James',
  lastName: 'Bond',
  sayHello() {
    // "this" viittaa "nykyiseen olioon"
    console.log(
      this.lastName + ', ' + this.firstName + ' ' + this.lastName + '.'
    );
    // "Bond, James Bond."
  }
};

        


        

          
this ei ole sidottu

          
    
            
  • 
              JavaScriptissä this-avainsana käyttäytyy eri tavoin kuin useimmissa muissa
              ohjelmointikielissä.
            
    • 
            
  • 
              this-avainsanaa voidaan käyttää missä tahansa funktiossa, vaikka se ei olisi olion metodi.
            
    • 
            
  • 
              HUOM: this-arvo määritetään ajon aikana riippuen kontekstista.
            
    • 
          

        


        

          
this ei ole sidottu (jatkuu)

          
    
            
  • Seuraavassa esimerkissä ei ole syntaksivirhettä:
    • 
          

          
let user = { name: 'John' };
let admin = { name: 'Admin' };

function sayName() {
  console.log(this.name);
}

// käytetään samaa funktiota kahdessa oliossa
user.f = sayName;
admin.f = sayName;

// näillä kutsuilla on eri this
user.f(); // "John"  (this == user)
admin.f(); // "Admin"  (this == admin)
admin['f'](); // (myös hakasulkunotaatio toimii)

        



        

          
Kutsu ilman oliota

          
function sayHello() {
          console.log(this);
        }
        
        sayHello(); // undefined (strict-tilassa)
        

          
    
            
  • 
              Tässä this on strict-tilassa määrittelemätön (undefined).
              Jos yritämme käyttää this.name-ominaisuutta tai muita, saamme virheen.
            
    • 
            
  • 
              Ei-strict-tilassa this viittaa globaaliin olioon
              (window selaimessa).
            
    • 
            
  • 
              Tämä on yleensä ohjelmointivirhe. Jos funktiossa on this,
              sen odotetaan olevan kutsuttu olion kontekstissa.
            
    • 
          

        


        

          
Sidottamattoman this-avainsanan seuraukset

          
    
            
  • 
              
    JavaScriptissä this-arvo:
    
              
      
                
    • määritellään kutsuhetkellä
      • 
                
    • 
                  ei riipu siitä, missä metodi on määritelty, vaan siitä, mikä olio
                  on "ennen pistettä" kutsuhetkellä
                
      • 
              
    
            
    • 
            
  • 
              
    
                Ajon aikana määriteltävän this-avainsanan käyttö tuo
                sekä etuja että haittoja.
              
    
              
      
                
    • funktiota voidaan käyttää uudelleen eri olioille
      • 
                
    • suurempi joustavuus lisää myös virhemahdollisuuksia
      • 
              
    
            
    • 
          

        


        

          
this-avainsanan asettaminen eksplisiittisesti

          
    
            
  • Metodit (funktiot olion ominaisuuksina)
    • 
            
  • 
              this
              
      
                
    • 
                  func.call(), func.apply(),
                  func.bind()
                
      • 
              
    
            
    • 
            
  • 
              Useiden samankaltaisten olioiden luominen
              
      
                
    • new-operaattori ja konstruktorifunktiot
      • 
              
    
            
    • 
          

        


        

          
this:n sitominen itse

          
    
            
  • 
              func.call()
              ja
              func.apply()
              - kutsu funktiota eri this:llä
            
    • 
            
  • 
              func.bind()
              - luo uusi funktio eri this:llä
            
    • 
          

        


        

          
func.call() ja func.apply()

          
    
            
  • 
              this:n sitominen eri objektiin funktion kutsuhetkellä
            
    • 
            
  • 
              func.call() - argumentit annetaan yksittäin
            
    • 
            
  • 
              func.apply() - argumentit annetaan taulukossa
            
    • 
            
  • 
              Molemmat kutsuvat funktion heti ja muokkaavat kontekstia. Ainoa ero on siinä, miten omat
                argumenttisi välitetään.
            
    • 
          

          
// Syntaksi
func.call(obj);
func.call(obj, param1, ..., paramN);

func.apply(obj);
func.apply(obj, [param1, ..., paramN]); // taulukko argumenttien välittämiseksi


        


        

          

            func.call() ja func.apply() esimerkki
          

          
let user = { name: 'John' };
let user2 = { name: 'Jane' };

function greet(city, state) {
  console.log(this.name + 'from' + city + ', ' + state);
}

greet.call(user, 'Dallas', 'Texas'); // "John from Dallas, Texas"
greet.call(user2, 'Miami', 'Florida'); // "Jane from Miami, Florida"

const args = ['Dallas', 'Texas'];
greet.apply(user, args); // "John from Dallas, Texas"
greet.apply(user2, ['Miami', 'Florida']); // "Jane from Miami, Florida"

        


        

          
func.bind()

          
    
            
  • 
              func.bind() -metodi
              luo uuden funktion, jolla kutsuttaessa on this -avainsana asetettu annettuun arvoon,
              ja annettu argumenttien sarja edeltää niitä, jotka annetaan, kun uutta funktiota kutsutaan.
            
    • 
            
  • 
              Ei kutsu funktiota, se vain mahdollistaa minkä tahansa objektin sitomisen, funktio on kutsuttava
                itse.
            
    • 
          

          
// Syntaksi
func.bind(obj);
func.bind(obj, param1, ..., paramN);

        


        

          
func.bind() esimerkki

          
let user = { name: 'John' };
let user2 = { name: 'Jane' };

function greet(city, state) {
  console.log(this.name + 'from' + city + ', ' + state);
}

const introduce = greet.bind(user2, 'Miami', 'Florida');
introduce(); // Tulostaa: "Jane from Miami, Florida"

        


        

          
this ja metodiketjutus suunnittelumallina

          
    
            
  • 
              Tärkeää tunnistaa, mitä tapahtuu
              
      
                
    • vain yksi lause, joka ketjuttaa kaikki metodit
      • 
              
    
            
    • 
          

          
let student1 = new Student()
  .setFirstName('Ahto')
  .setLastName('Simakuutio')
  .setCourseName('Web Site Development')
  .setEntryYear(2025)

        


        

          
Ei-ketjutus vs. metodiketjutus

          

            

              
class Student1 {
  constructor() {
    this.firstName = '';
    this.lastName = '';
  }
  setFirstName(value) {
    this.firstName = value;
  }
  setLastName(value) {
    this.lastName = value;
  }
}

              
    
                
  • metodit eivät palauta mitään
    • 
                
  • metodit on kutsuttava erikseen
    • 
              

            

            

              
class Student2 {
  constructor() {
    this.firstName = '';
    this.lastName = '';
  }
  setFirstName(value) {
    this.firstName = value;
    return this;
  }
  setLastName(value) {
    this.lastName = value;
    return this;
  }
}
            

              
    
                
  • metodit palauttavat this:n
    • 
                
  • metodikutsuja voidaan ketjuttaa
    • 
              

            

          

        


        

          
Ei-ketjutus vs. metodiketjutus (jatkuu)

          

            

              
Ei-ketjutus

      
// kutsu jokainen metodi erikseen
let s1 = new Student1();
s1.setFirstName('Ahto');
s1.setLastName('Simakuutio');

    

    

      
Metodiketjutus

      
// ketjuta metodit
let s2 = new Student2()
  .setFirstName('Ahto')
  .setLastName('Simakuutio');

            

          

        


        

          
Metodiketjutus

          
    
            
  • 
              Metodi palauttaa this:n
              
      
                
    • objekti itse palautetaan metodista
      • 
                
    • 
                  toisen metodin kutsuminen samassa objektissa voidaan ketjuttaa
                
      • 
              
    
            
    • 
            
  • 
              Getterit ja muut metodit, jotka palauttavat muuta dataa, eivät voi olla ketjutettuja
            
    •
