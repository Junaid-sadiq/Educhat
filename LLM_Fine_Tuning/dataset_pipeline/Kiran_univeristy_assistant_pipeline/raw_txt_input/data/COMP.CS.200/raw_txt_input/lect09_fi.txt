Tapahtumien kulkeutuminen Tapahtumien kulkeutuminen: bubbling ja capturing Tapahtumat kulkeutuvat DOM:ssa kolmessa vaiheessa: Capturing-vaihe: Tapahtuma kulkee alas juuresta kohde-elementtiin div1⬇️ div2⬇️ div3⬇️ div4⬇️ form⬇️ Tavoitteessa: tapahtuma saavuttaa kohteen Bubbling-vaihe: tapahtuma lähtee etenemään takaisin juurta kohti div1⬆️ div2⬆️ div3⬆️ div4⬆️ form⬆️ Huom: Tapahtumankuuntelijat asetetaan yleensä joko bubbling- tai capturing-vaiheeseen. Jos molempia käytetään, capturing tapahtuu ensin. Tapahtumien leviämisen pysäyttäminen event.stopPropagation() pysäyttää tapahtuman leviämisen ylös- tai alaspäin DOM:ssa, estäen vanhempia/esivanhempia tai lapsia/jälkeläisiä elementtejä vastaanottamasta sitä. Sen tarkoitus on hallita tapahtumavirtaa ja estää ei-toivotut sivuvaikutukset, eristäen tapahtumankäsittelyn tiettyihin elementteihin. Käyttötapaukset vanhempien käsittelijöiden estäminen (yleisempi käyttötapaus) mukautettujen ohjainten luominen: interaktiivisten komponenttien rakentaminen, jotka vaativat tarkkaa hallintaa tapahtumavirran suhteen esimerkki: Mukautettu pudotusvalikko uudelleenkäytettävien käyttöliittymäkomponenttien luomisessa, stopPropagation voi estää komponentin tapahtumankuuntelijoita häiritsemästä ympäröiviä sovelluksia kaikki suuret JavaScript-kehykset (React, Angular, Vue.js) perustuvat pohjimmiltaan DOM:n tapahtumajärjestelmään ja abstrahoivat suoran DOM-manipuloinnin, mutta toimivat silti taustalla olevan tapahtumamallin kanssa. Tapahtumien delegointi tehokkuuden vuoksi Sen sijaan, että liittäisit tapahtumankuuntelijoita jokaiseen yksittäiseen elementtiin, tapahtumien delegointi liittää yhden kuuntelijan vanhempaan elementtiin. Tämä kuuntelija määrittää sitten, mikä lapsielementti laukaisi tapahtuman. Edut: vähemmän tapahtumankuuntelijoita tarkoittaa vähemmän muistin käyttöä ja nopeampaa käsittelyä käsittelee tapahtumia elementeissä, jotka lisätään DOM:iin kuuntelijan liittämisen jälkeen vähentää tarvetta toistuvaan tapahtumankuuntelijoiden asettamiseen Esimerkki: "Asiakas"-toimintojen käsittely Asiakas A Asiakas B Asiakas C Asiakas A... const customerList = document.getElementById('customerList'); customerList.addEventListener('click', function(event) { if (event.target.classList.contains('customer')) { const customerId = event.target.dataset.customerId; console.log('Asiakas klikattu:', customerId); // Suorita toimenpiteitä customerId:n perusteella alert(`Asiakas ${customerId} klikattu!`); } }); Oletustoiminnon estäminen Esimerkiksi button-elementin oletustyyppi on submit, joka laukaistaan klikkaustapahtumalla Estääksesi tämän, käytä event.preventDefault(), joka pitää käyttäjät samalla sivulla: Ei ei-toivottuja päivityksiä. antaa kehittäjille paremman hallinnan päättää, milloin ja miten toiminto tapahtuu toimii JavaScript-ohjatuissa lomakkeissa: tarvitaan AJAX-pyyntöihin estämään koko sivun uudelleenlataus olennaista yksisivuisissa sovelluksissa (SPA), jotka on tehty Reactilla ja Angularilla document.getElementById("myButton").addEventListener("click", function(event) { event.preventDefault(); // Estää oletuslomakkeen lähetyksen }); Estääksesi tapahtumien leviämisen (esim. estääksesi tapahtuman kuplimisen ylös DOM-puussa), käytä event.stopPropagation(): element.addEventListener('click', function(event) { event.stopPropagation(); // Estää tapahtuman leviämisen edelleen }); Keskeiset erot: event.preventDefault() → Estää oletusselaimen toiminnan (esim. lomakkeen lähetys, linkin navigointi). event.stopPropagation() → Estää tapahtuman leviämisen ylös tai alas DOM-puussa.
