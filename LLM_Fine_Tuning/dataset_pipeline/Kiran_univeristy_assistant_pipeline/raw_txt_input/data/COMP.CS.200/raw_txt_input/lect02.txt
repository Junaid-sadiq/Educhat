Some of them are used to define the semantics of the document further and some of them provide new functionality. A good overview of important semantic elements can be found from Dive Into HTML5. There are plenty of new elements for embedding content, such as <video> (for videos) and <canvas> (for interactive bitmap graphics). Benefits: improved accessibility, search engine optimization (SEO), maintainability Towards more semantic tagging in HTML5 Semantic tags are to add specific meaning and categorize the content of an HTML page: less formatting - more semantics. A page layout suggestion: header: the starting point for a document. Typically, it contains the introduction nav: placeholder for navigation info, such as links section: sections for content article: independent content that is extractable and still makes sense aside: placeholder for additional info as a sidebar footer: typical footer information includes authors, copyrights, contact information Semantic vs. generic block-level elements These elements have a specific meaning and purpose in the structure of a web page, conveying information to both browsers and users. article aside blockquote dl, dd, dt figcaption, figure footer, header, hr li, main, nav ol, pre, section ul <div> The `div` element is a generic block-level container used to group content without any inherent meaning. Use cases id if no specific semantic element exists frameworks or libraries rely on `div` temporary layouts (development only) Note: even with `div`, use descriptive class names for clarity. Whether it is a void element (self-closing). Its categorization within content models such as flow, sectioning, and interactive. Permitted ARIA roles, crucial for accessibility.
