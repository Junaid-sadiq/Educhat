Introduction to the DOM

How did we get here?

  • The problem: static web pages were not interactive, dynamic, or responsive.
  • Partial fix: JavaScript that developers can use to add interactivity.
    • The Problem: JavaScript cannot directly access or modify the content of an HTML document
    • Solution: The DOM API

What is the DOM?

"The W3C Document Object Model (DOM) is a platform and language-neutral interface that allows programs and scripts to dynamically access and update the content, structure, and style of a document." - W3C

  • W3C (World Wide Web Consortium) standard, first published in 1998.
    • Core DOM - standard model for all document types - W3C DOM Specifications
    • XML DOM - specializes in parsing, validating, and manipulating XML documents - XML DOM Level 3 Core Specification
  • HTML DOM - what we use on our webpages - HTML Living Standard - DOM

The HTML DOM is a model of a web page, structured as a tree, which the browser constructs upon loading the page. This is also known as the DOM tree.

Click here to learn more

What is the DOM tree?

  • A hierarchical representation of the web page's structure
    • element can have parent, children, and siblings
    • in HTML document the root is always <html> element and it contains two mandatory children: head and body
    • the nesting element is considered as a parent, inner elements are children
    • rootward traversal enables the retrieval of ancestor nodes
  • Elements can be accessed and manipulated using JavaScript

Example of a DOM tree

<html lang="en">
    <head>
        <title>My Document</title>
    </head>
    <body>
        <h1>Header</h1>
        <p>Paragraph</p>
    </body>
</html>

Document represents the whole DOM tree

  • The hierarchy as defined
  • Grants access to global properties and information 
    const title = document.title // returns the title of the document
const url = document.URL // returns the URL of the document
const contentType = document.contentType // e.g. 'text/html'
  • manipulate the document's structure and content 
    document.title = 'New Title' // sets the title of the document to 'New Title'
// sets the background color of the body element to light blue
document.body.style.backgroundColor = 'lightblue' 
//Access the first p element in the document
const p = document.querySelector('p')
  • Can be accessed using the document object

The DOM API

How to use the DOM API

  • The DOM API provides a set of interfaces and methods that allow programs and scripts to access and update the content, structure, and style of a document through the DOM tree, such as:
    • interaction through event handling, like clicks and form submissions
    • access to the document's structure and content
    • dynamic manipulation of the document
  • Example of DOM usage through the DOM API: 
    const paragraphs = document.querySelectorAll("p");
console.log(paragraphs[0].nodeName); // Outputs 'P'

Accessing Elements (The Older Way)

  • getElementById : Selects a single element by its unique ID. 
    const demoElement = document.getElementById("demo"); 
                // Returns a single element with id="demo"
  • getElementsByClassName : Selects all elements with a specific class name. 
    const demoElements = document.getElementsByClassName("demo"); 
                // Returns a collection of elements with class="demo"
  • getElementsByTagName : Selects all elements with a specific tag name. 
    const demoElements = document.getElementsByTagName("div"); 
                // Returns a collection of all div elements

Accessing Elements (The Newer Way)

  • querySelector : Selects the first element that matches a CSS selector. 
    let demoElement = document.querySelector(".demo"); 
                // Selects the first element with class "demo"
                
                demoElement = document.querySelector("#demo"); 
                // Selects the element with id "demo"
                
                demoElement = document.querySelector("div"); 
                // Selects the first div element
  • querySelectorAll : Selects all elements that match a CSS selector. 
    const demoElements = document.querySelectorAll(".demo"); 
                // Selects all elements with class "demo"
                
                demoElements = document.querySelectorAll("div"); 
                // Selects all div elements

Accessing Elements: Older vs. Newer Methods

  • Specificity:
    1. older: More restricted—selects by ID, class, or tag name.
    2. newer: More flexible—supports full CSS selectors (similar to jQuery).
  • Collection Type:
    1. older: Returns an HTMLCollection (live collection).
    2. newer: Returns a NodeList (static collection).
  • Browser Support:
    1. older: Supported in all browsers.
    2. newer: Supported in modern browsers (IE9+).

Accessing Element Content

<div id="demo"><p>This is a <span style="display: none;">hidden</span> paragraph</p></div>
  • innerHTML : Gets or sets the HTML content of an element (use with caution!) 
     element = document.getElementById("demo")
console.log(element.innerHTML) 
// Outputs: '<p>This is a <span style="display: none;">hidden</span> paragraph</p>'
  • innerText : Gets or sets the visible text content of an element 
     element = document.getElementById("demo")
console.log(element.innerText)

  • textContent : Gets or sets the text content of an element, including hidden text 
     element = document.getElementById("demo")
console.log(element.textContent)
// Outputs: 'This is a hidden paragraph'

Accessing Element Attributes

  • getAttribute : Retrieves the value of a specified attribute 
     const src = document.getElementById("myImage").getAttribute("src");
  • setAttribute : Sets the value of a specified attribute 
     document.getElementById("myImage").setAttribute("src", "landscape.jpg");
  • removeAttribute : Removes a specified attribute 
     document.getElementById("myImage").removeAttribute("src");
  • hasAttribute : Checks if an element has a specified attribute 
     const hasSrc = document.getElementById("myImage").hasAttribute("src");

Accessing Element Styles

  • style : Accesses and modifies the inline styles of an element 
     document.getElementById("demo").style.color = "red";
  • classList : Accesses and modifies the class attribute of an element 
     document.getElementById("demo").classList.add("red") // adds a class
 document.getElementById("demo").classList.remove("red") // removes a class
 document.getElementById("demo").classList.toggle("red") // toggles a class
  • getComputedStyle : Retrieves the values of all CSS properties of an element 
     const styles = window.getComputedStyle(document.getElementById("demo")); // retrieves the computed styles
 const color = styles.getPropertyValue("color"); // retrieves the value of a specific style

Accessing Element Dimensions

  • getBoundingClientRect : Retrieves the size and position of an element 
     const rect = document.getElementById("demo").getBoundingClientRect();
  • clientWidth and clientHeight : Retrieves the width/height of an element, including padding but not border 
     const width = document.getElementById("demo").clientWidth;
  • offsetWidth and offsetHeight : Retrieves the width/height of an element, including padding and border 
     const width = document.getElementById("demo").offsetWidth;
  • scrollWidth and scrollHeight : Retrieves the width/height of an element, including padding, border, and scrollbar 
     const width = document.getElementById("demo").scrollWidth;

Creating and Inserting Elements

  • createElement : Creates a new element 
     const newElement = document.createElement("p");
  • append : Inserts a new element as the last child of a parent element 
     document.getElementById("demo").append(newElement);
  • prepend : Inserts a new element as the first child of a parent element 
     document.getElementById("demo").prepend(newElement);

Other methods for creating and inserting: appendChild, createTextNode , insertBefore createDocumentFragment , cloneNode , insertAdjacentHTML ,

Removing and Replacing Elements

  • remove : Removes an element from the DOM 
     document.getElementById("demo").remove();
  • removeChild : Removes a specified child element from a parent element 
     document.getElementById("demo").parentNode.removeChild(document.getElementById("demo"));
  • replaceChild : Replaces a specified child element with a new element 
     const newElement = document.createElement("p");
    document.getElementById("demo").parentNode.replaceChild(newElement, document.getElementById("demo"));

Cloning Elements

  • cloneNode : Creates a copy of an element, with the option to include or exclude child elements 
     const clone = document.getElementById("demo").cloneNode(true); // true = deep copy, false = shallow copy
  • Deep copy: Includes all child elements and their attributes
  • Shallow copy: Only includes the element itself and its attributes

Introduction to Events

  • JavaScript is an event-driven programming language, meaning its execution flow is primarily determined by events rather than a strict linear sequence.
  • Events are triggered by:
    • user actions: hovers, scrolling, keypresses, form submissions, and many more...
    • programs: JavaScript can generate events through direct method calls or by dispatching custom events, enabling dynamic behavior. 
      // Triggering a click event programmatically
document.getElementById("myButton").click();

// Triggering a change event
document.getElementById("myInput").dispatchEvent(new Event("change"));
    • scheduled actions: timers like `setTimeout` and `setInterval` schedule events to be added to the JavaScript event queue
      • setTimeout(callback, delay) tells the runtime to wait at least delay milliseconds and then queue an event
      • the callback is the function you provide to setTimeout or setInterval
      • Note: setTimeout(callback, 0) doesn't execute the callback instantly, but but queues an event to trigger the `callback` when the sync callstack is empty
  • Event handlers: functions that are called when an event occurs

The Event object (Part 1)

When an event is triggered, an event object is created:

  • contains information about the event
  • can be used to control the event's behavior
  • can be passed to event handlers
function logEvent(event) {
    console.log(event); // Outputs the event 
}

element.addEventListener("click", logEvent);

  • callback as function identifier, no braces

Event Listeners Example: Memory Leak

function handleClick() {
    console.log('Button clicked');
}

const button = document.getElementById('myButton');
button.addEventListener('click', handleClick);

// Later in the code...
button.parentNode.removeChild(button); // Removes the button from the DOM

Even though the button is removed from the DOM, the event listener is still attached to the button. This can cause a memory leak.

To avoid memory leaks, always remove event listeners when they are no longer needed. 

button.removeEventListener("click", handleClick);
button.parentNode.removeChild(button);

Closer look to a closure in wrapper

function createHandler(num, text) {
    return function (event) {  //closure!!!
        console.log("Number:", num, "Text:", text);
        console.log("Event object:", event);
    };
}

document.getElementById("myButton")
    .addEventListener("click", createHandler(42, "Hello!"));

    A closure is a function that "remembers" variables from its outer scope even after that scope has finished executing.

  • The inner function is a closure that remembers num and text of outer function
  • Closures retain access to their outer function's variables
  • Then, when createHandler(42, "Hello!") runs, it returns a function that stores these values.

Where does the wrapper's event come from?

  • The returned anon. function is assigned to addEventListener, but it does not execute yet
  • The event object is automatically passed as the first parameter to event listeners.
  • When the event occurs, the event listener provides the event object to the callback function.
  • This allows access to both the preserved variables (num, text) and the event data.

Event propagation

Event Propagation: bubbling and capturing

Events propagate through the DOM in three phases:

  1. Capturing phase: The event travels down from the root to the target element

  2. Target phase: the event reaches the target

  3. Bubbling phase: The event bubbles up from the target element to the root

Note: Event listeners are usually set for either bubbling or capturing. If both are used, capturing occurs first.

Stopping event propagation

event.stopPropagation() stops an event from traveling further up or down the DOM, preventing parent/ancestor or child/descendant elements from receiving it.

Its purpose is to control event flow and prevent unintended side effects, isolating event handling within specific elements.

Use Cases

  • preventing parent handlers (more usual use case)
  • creating custom controls:
    • building interactive components requiring precise control over event flow
    • example: A custom dropdown
  • in creating reusable UI components, stopPropagation can prevent the component's event listeners from interfering with the surrounding applications
    • all major JavaScript frameworks (React, Angular, Vue.js) fundamentally rely on the DOM's event system and abstract away direct DOM manipulation but still work with the underlying event model.

Event delegation for efficiency

Instead of attaching event listeners to every individual element, event delegation attaches a single listener to a parent element. This listener then determines which child element triggered the event.

Benefits:

  • fewer event listeners mean less memory usage and faster processing
  • handles events on elements added to the DOM after the listener is attached
  • reduces the need for repetitive event listener setup

Prevent default

  • For example, a button's default type is submit triggered by click event
  • To prevent this, use event.preventDefault() which keeps users on the same page: No unwanted refreshes.
  • gives developers better control to decide when and how the action happens
  • works with JavaScript-driven forms: needed for AJAX requests to prevents from full page reload
  • essential for SPAs (Single Page Applications) done with React and Angular
document.getElementById("myButton").addEventListener("click", function(event) {
    event.preventDefault(); // Prevents the default form submission
});

To prevent event propagation (e.g., stopping an event from bubbling up the DOM tree), use event.stopPropagation(): 

element.addEventListener('click', function(event) {
    event.stopPropagation(); // Stops the event from propagating further
});

Key Differences:

  • event.preventDefault() → Prevents the default browser behavior (e.g., form submission, link navigation).
  • event.stopPropagation() → Stops the event from traveling up or down the DOM tree.
