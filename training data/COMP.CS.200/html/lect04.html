Forms

  • Forms serve various purposes, such as
    • facilitating transactions in web stores
    • conducting searches in engines and databases
    • collecting data in polls and registration sites
  • Information from forms is typically transmitted to a server via HTTP transactions.
  • Forms can also submit data directly to the web page itself.
  • A form typically consists of one or more user inputs, including
    • text fields
    • checkboxes
    • radio buttons
    • select boxes
    • ..but the most versatile element is <input>

input types
implicit association also possible

  • the default value of type is text.
  • other types include number and more elaborate types, such as:
    password - hides the input

    tel - validates the phone number

Constructing a form

action (form-handler)

<form action="form-handler" method="GET" | "POST">
    [input widget]*  {submit button}
</form>
  • action specifies a form handler, often a URL
    • if left blank results in the form data being submitted back to the same page
    • formruns on a separate server to process form data.
    • written in server-side languages like PHP, Perl, or node.js (like WebDev1).
    • server-side programming covered in this other courses
  • method specifies how data is sent using the HTTP method (GET or POST).

GET method

For demo purposes, this:
  • a browser sends a request to a server
  • method defaults to GET
  • the form data is attached to the address as a query string:
    • ?key=value[&key=value]*
    • key is connected to a value with equal sign (=)
    • pairs are separated with &
  • GET can be used, if values being visible is not an issue
  • search engines often use the GET method
    • gives a possibility to save the query and send it to other users
    • queries can be sent even without the form

POST method

  • a browser sends a request to a server
  • the input data is sent in the body of HTTP request
  • the data is hidden from the user and other onlookers
  • yet with the POST method the data is still open (not encrypted)
  • a third party is capable of reading the sent data (also the password)
  • sensitive data between must be sent with HTTPS protocol that is SSL-encrypted

Form validation

Form validation

  • Before submission, the data should be checked
    • check the user's input directly on their browser to prevent invalid or incomplete data from being sent to the server, resulting in benefits such as:
      • reduced server load: the server only handles valid data, minimizing processing overhead
      • improved user experience: providing real-time feedback on invalid input allows users to correct mistakes immediately
      • reduced traffic: only valid data is sent, decreasing the amount of data transmitted between the client and server
  • also security is crucial: proper validation and sanitization can prevent malicious attacks like injections

Validation means

  • useful frontend-side checks as HTML constraint validation:
    • appropriate input field types, e.g., mail
    • attributes such as required, max or min-length
    • pattern attribute for arbitrary checks
  • submit button and its click event bound validation function (javascript validation)

pattern with regular expressions

  • input value must match the given pattern
  • pattern is given as a regular expression
  • pattern is checked before sending the form

regular expressions (regexp) is a versatile language

Regular expression

char class [quantifier]

\d{7} //digit for seven times

Regular expression: char class [quantifier]

regexp matches..
a one character that is a
abc a, followed by b and c
a* 'a' for zero or more times
a+ 'a' for one or more times
a? 'a' for one or zero times
^a string starts with 'a'
[^a] no 'a'. For example,
/c[^a]/.test("ca") false
/c[^a]/.test("cb") true
a|b either 'a' or 'b'
[abc] either 'a', 'b' or 'c'
[^abc] neither 'a', 'b' nor 'c'
[a-z] char between a-z, lowercase
[0-9] number between 0-9
[ -] space or dash
/d digit
/w alphanumeric
a.c 'a' followed by any char and then 'c'
a{5} 'a' for five times
a{5,7} 'a' for five, six or seven times

Examples of regular expressions

[Mm].*k A single character that is an upper or lowercase 'm', followed by zero or more characters of any type, followed by a single lowercase 'k'
[A-Z][a-z]+ A single upper case character followed by one or more lower case letters
[0-9]{3}[ -][0-9]{7} A simple match for a Finnish domestic phone number — three numbers, followed by a space or a dash, followed by seven numbers
