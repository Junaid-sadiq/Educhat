Global attributes

  • Global attributes are attributes used in all elements, such as:
    accesskey, class, contenteditable, contextmenu, dir, draggable, dropzone, hidden, id, lang, spellcheck, style, tabindex, title, translate
  • The most important attributes are id and class.
  • In some cases, attribute can be without value if; the attribute is then called unary or boolean attribute (e.g. checked or disabled)

id attribute

  • id must be unique within a document
  • the element with id "part1" is referred by using # character: #part1
  • the id can be used, for example, to create a link to the position of id in the html document, e.g., index.html#part1

Strings in HTML

Strings in HTML are defined with quotation marks, which can be either single (') or double ("). Attribute values, for instance, are represented as strings enclosed within these quotation marks. Additionally, styles can be defined interchangeably using either single or double quotation marks.

<p id="part1"></p>
<p id='part2'></p>
<p id=part3></p>

because a browser knows to expect a string, quotation marks can be left out. This is not always the case, e.g.

<p class="emphasized noprint">
In interpreting the attribute value, the quotation marks are decisive, thus, use quotation marks

Characters

  • encoding with UTF-8
  • escaping

Character Encoding

  • HTML code is saved as text in a file
  • in the process the code is encoded (effective when turned into binary numbers), e.g.,
    • ASCII: Original 127 chars, limited to letters, characters and some symbols
    • ISO-8859-1(Latin1): Western chars based on the Arabic script
    • -ISO/IEC-8859-15: Modified ISO-8859-1 to support French, Finnish, and Estonian
    • Windows-1252: Superset of ISO-8859-1 (additional symbols)
    • Unicode: contains characters for most living languages and scripts in the world in basic multilingual plane (BMP), and also emojis in astral planes

Unicode as UTF-8

  • Unicode can be implemented using different encodings: -8, -16, -32
  • nowadays UTF-8 is the most dominant
    • must be both 
      <meta charset="utf-8" />
      and the real encoding of a file
    • uses variable lengths for characters and symbols
    • capable of encoding over 1 million characters
    • backward-compatible with ASCII
      • the first 128 characters encoded with the same codes as in ASCII

Character escapes (HTML entities) as ASCII workaround

  • A way of representing characters when:
    • a char is not available
    • a char conflicts with the syntax (e.g., <, >)
    • a char is invisible or ambiguous
    • ASCII encoding must be used, e.g., in URLs

Semantic elements in HTML5

Semantic elements in HTML5

There are a fair number of new elements HTML5. Some of them are used to define the semantics of the document further and some of them provide new functionality.

A good overview of important semantic elements can be found from Dive Into HTML5.

There are plenty of new elements for embedding content, such as <video> (for videos) and <canvas> (for interactive bitmap graphics).

Benefits: improved accessibility, search engine optimization (SEO), maintainability

Towards more semantic tagging in HTML5

Semantic tags are to add specific meaning and categorize the content of an HTML page: less formatting - more semantics. A page layout suggestion:

header: the starting point for a document. Typically, it contains the introduction
nav: placeholder for navigation info, such as links
section: sections for content
article: independent content that is extractable and still makes sense
aside: placeholder for additional info as a sidebar
footer: typical footer information includes authors, copyrights, contact information

Semantic vs. generic block-level elements

These elements have a specific meaning and purpose in the structure of a web page, conveying information to both browsers and users.

  • article
  • aside
  • blockquote
  • dl, dd, dt
  • figcaption, figure
  • footer, header, hr
  • li, main, nav
  • ol, pre, section
  • ul
<div>

The `div` element is a generic block-level container used to group content without any inherent meaning.

Use cases

  • id if no specific semantic element exists
  • frameworks or libraries rely on `div`
  • temporary layouts (development only)

Note: even with `div`, use descriptive class names for clarity.

W3C content model

W3C content models

HTML's content model has transitioned from a simple inline/block model to a more nuanced and semantic system in HTML5.

  • block => flow
  • inline => phrasing

The content model defines the expected structure of each HTML element by specifying:

  • Its permitted ancestors and descendants, dictating its position within the document tree.
  • Whether it is a void element (self-closing).
  • Its categorization within content models such as flow, sectioning, and interactive.
  • Permitted ARIA roles, crucial for accessibility.
