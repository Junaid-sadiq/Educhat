Why are we pushing FP?

  • To grasp the intricate nature of JavaScript, one must delve into functional programming
  • Functions serve as the Swiss Army knives of JS, akin to queens on a chessboard
  • Functional programming (FP) promotes cleaner, more concise code by focusing on immutable data and pure functions.
  • FP encourages better code organization, reduces side effects, and facilitates easier debugging and testing.
  • By embracing FP principles, developers can leverage the full power of JavaScript and build more robust and scalable applications.
  • Next phases in webdev path, such as React, Redux, Vue and Elm are functional

Pure functions

  • cause no side-effects, such as
    • changes to their params, global variables or DOM
    • use AJAX or timers
    • logs to console
  • do not depend on state
  • return always the same output for an input, i.e., they are idempotent
    • thus they must not rely on indeterminate values, such as Math.random() or Date

First-class functions

Function as the first-class citizen

  • a function can be
    • a variable
    • passed as a parameter, such as callbacks (cb) in:
      • element.addEventListener(type, cb)
      • setTimeout(cb, timeout)
      • higher-order functions: map(), filter() and reduce()
    • return value

Function as a variable

function a(){console.log("I am a")}; a()
const b = () => {console.log("I am b")}; b()
const c = console.log; c("I am c")
  • a is a traditional function definition
  • b is a function expression, it is defined as an arrow function
  • c is a variable that is a function
  • both b and c are invoked with () operator, also called as invocation- or call operator

Function as a return type

const c = () => console.log; 
c()("I am c")
  • here c returns an arrow function
  • which gets executed with ()
  • it returns console.log
  • which gets called with a parameter ("I am c")

Function as an argument

const d = (par, f) => f(par);
d("I am d", console.log)
  • d gets two parameters: par and f
  • d calls f with par
  • resulting in "I am d"

Arrow functions

Arrow function

  • new in ES6, intended to shorten the syntax
  • remove ambiguity about the current this object

Two function expressions: conventional and arrow function

const sayHello = 
function (greeting,sname) {
  console.log(greeting + " " + sname);
}
const sayHello = 
  (greeting,sname) => 
    console.log(`${greeting} ${sname}`);

Arrow function syntax

  • params are followed by an arrow and statements 
    (param1, param2) => { statement1; statement2}
  • if one param, no brackets needed 
    param1 => {statement1; statement2}
  • if one statement, no curly brackets needed 
    (param1, param2) => statement1;
  • if no params, round brackets are needed 
    () => statement1;
  • implicit return 
    x=>x*2
    returns x multiplied by two
  • What does then the following function do? 
    item => item

Arguments of an enclosing scope

Conventional

// implicit arguments binding
function test(n) {
  const f = () => arguments[0] + n; 
  // f sees variables of test (closure)
  // both n and arguments
  // where arguments[0] is n
  return f();
}
test(3); // 6

Arrow

const arguments = [1, 2, 3];
const arr = () => arguments[0];
// ref. to a global variable
arr(); // 1

Arguments

Conventional

  • the number of params may vary
  • the variation handled with the arguments object
  • useful especially if more arguments than formally declared, which often happens with variadic functions, e.g. Math.min()

Arrow

  • NO arguments object
  • in the previous example, arrow function sees the arguments object of the enclosing scope
  • → closure

Array functions

Array functions

  • map()
  • filter()
  • reduce()
  • used to replace loops (for, while)
  • often implemented by calling arrow functions
  • are so called 'higher-order functions': functions calling functions

map()

Syntax:

const new_arr = arr.map(function cb( currentValue[, index[, array]]) 
{ return currentValue; } [, thisArg]); 
//thisArg - optional, value for 'this' in callback
  • calls cb for each item
  • returns a new array
    • has the same length as the old one
    • had it a different length, it would make map anti-pattern
  • corresponds to a math function: maps a domain to a range

For example:

const arr=[1,2,3,4,5];
const new_arr1 = arr.map(function(item){return item*2}); //[2,4,6,8,10], traditional
const new_arr2 = arr.map(item=>item+1);                  //[2,3,4,5,6], arrow-function

filter()

let newArray = arr.filter(callback(element[, index, [array]])[,
thisArg]) //thisArg - optional, value for 'this' in callback
  • cb called for each array item
  • cb returns
    • true to keep the element
    • false to discard the element
  • returns a new filtered array of kept elements

reduce()

arr.reduce(cb( accumulator, currentValue[, index[, array]])
    [, initialValue])
  • cb called for each item
  • returns the accumulator
    • the prev. return value
  • used to fold an array into a single value,
    • e.g., sum or min/max
  • initial value is mandatory for an array of objects
    • 99% of the time you handle an array of objects

reduce() with the array of primitives

Using two parameters, accumulator and the current item. The initial value is set to zero:

const total = [1,2,3].reduce((acc, i)=>acc+i, 0);

.. works also without it:

const total = [1,2,3].reduce((acc, i)=>acc+i);

Adding more parameters, index and arr

const avg = [1,2,3].reduce((acc, i, index, arr)=>
    index<arr.length-1?acc+i:(acc+i)/(index+1), 0);

reduce() with the array of objects

Calculate the sums of prices for each category

const shoppingCart = [
{"name": "toothbrush","category": "hygiene","price": 2.99},
{"name": "offBrandCoke","category": "foodAndDrinks","price": 0.99},
{"name": "offBrandHamburger","category": "foodAndDrinks","price": 1.49},
{"name": "offBrandFries","category": "foodAndDrinks","price": 1.49}]
//imperative style
const l = shoppingCart.length;
const obj={};
for (let i=0;i<l; i++){
  const category=shoppingCart[i]["category"]
  const price = shoppingCart[i]["price"]
  obj[category]=(obj[category]||0)+price;
}
//fp style
const pricesByCategory = shoppingCart.reduce((obj,item) => {
    obj[item["category"]]=(obj[item["category"]] || 0)+item["price"];
    return obj;
}, {})

WSD promotes following FP features

  • const
    • to pave the way for immutability
    • more robust programs
    • easier bug tracking
  • lambdas
  • higher-order functions, e.g., map(), filter() and reduce()
    • make code more expressive
      • e.g., map() is better than for loop - return a new array instead of modifying the old one => immutability
      • no state because no reassignable counters
      • no accidental global vars
      • no such errors as infinite loops or off-by-one either
  • In assignment, eslint rules: prefer-const and fp/no-loops
