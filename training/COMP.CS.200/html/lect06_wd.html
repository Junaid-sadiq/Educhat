CSS

Styling with selectors and combinators

CSS

Cascading Style Sheets or CSS for short defines the outlook of HTML.

It can be set in three different ways, with:

  • style attribute inside an element
  • a separate <style> element
  • a separate CSS file that is linked to the HTML document <link> element.

Loading style sheets from separate CSS file that are linked in the <head> element is preferred. One file can be used on multiple pages - meaning that changing the style will affect all of them.

CSS Examples

1. style attribute:

<p>Some text and <span style="color: blue;">some blue text</span></p>

2. <style> element:

<head>
    <title>A simple page</title>
    <style> h1 { border-bottom: 2px solid black; }</style>
</head>

3. a separate CSS file:

<html>
    <head>
        <title>A simple page</title>
        <link rel="stylesheet" href="my_awesome_style.css">
    </head>
    <body>
        <h1>Some content</h1>
    </body>
</html>

CSS rule syntax

Syntax of a CSS rule is SelectorList {declaration}.

/* General rule */
selector[, selector] {
  [property: value;]
}

/* The same rule targeted at several elements */
// Headers blue
h1, h2 {
  color: blue;
}

/* Several rules targeted at the same element */
// Page with black text on yellow background
body {
  color: black;
  background-color: yellow;
}

Classes as selectors

Also class selectors can be used without an element.

Any element with the class is then affected.

With the rule

.green_text { color: green }

both h1 and span, and any other element with the class of green_text will be affected.

<h1 class="green_text">Ugly Heading</h1>
<p>Lorem ipsum <span class="green_text">sit dolor</span> amet.</p>

Selector chaining

dot-concatenated classes target elements having all the listed classes defined, e.g.:

p.old.python_code { text-decoration:line-through; }
<p class="old python_code">print "Hello world!"</p> <!-- affected -->
<p class="new python_code"> print("Hello world!")</p> <!-- not affected -->

Note the space between old and python_code in HTML.

Multiple tag types, classes and ids can be selected with comma:

/* Affects all h1, h2, and h3 elements */
h1, h2, h3 { font-family: serif; }

Combinators

Descendant combinator (" ") selects all elements contained inside the parent.

/* All li elements inside element with "important" id */
#important li { font-weight: bold; }

Child combinator (">") selects immediate children of the parent element.

/* All h2 that are immediate children of element with id of content */
#content > h2 { font-weight: bold; }

Sibling combinator ("~") selects any elements that share the same parent after the first selector.

/* Any p that share the same h1 parent with h1 that are after h1 */
h1 ~ p { font-weight: bold; }

Next sibling combinator ("+") selects the element which is immediately after the defined sibling.

/* Selects p elements that are immediately after h1 */
h1 + p { font-weight: bold; }

Pseudo-elements

Pseudo-elements may be appended to a selector.

They affect specific parts of the elements in target, e.g., p::first-line will affect the first lines of paragraphs.

In CSS3 (CSS has versions too), double colons ("::") are used to distinguish pseudo-elements from -classes (":"), coming next.

The pseudo-elements are:

  • ::first-letter
  • ::first-line
  • ::after
  • ::before
  • ::selection (non-standard)

Content

A content property that can be used to insert new content into a page in combination with pseudo-elements:

/* Will insert the word Chapter and a
  space before any text inside h1-element */
  h1::before  { content: "Chapter "; }

See MDN for more examples and details.

Fonts, font-family

font-family declarations control what fonts are used for the selector. Its value is comma separated list of fonts (a font stack) that should have a generic family as the last item.

If the first font on the list is not found, the next one is tried until a font is found. The generic families for the fonts are: serif, sans-serif, monospace, cursive, and fantasy.

p.ingress {
    font-family: "Gill Sans", Georgia, "Times New Roman", serif;
}

  • font-weight

  • text-decoration

There are various ways for defining font-size

  • Relative sizes:

  • Length values

  • Percentage:
    • e.g. font-size: 80%

Specificity/cascading

Rules to solve style conflicts

  • Specificity selectors have a certain specificity value the rule with the most specific selector "wins"
  • Cascading (location) when several rules have same specificity value, the "last" rule wins
  • Inheritance some properties are inherited from their parent (not all)

Specificity formula

When multiple styles overlap, the ascending order of specificity defines the end result (the strongest last):

Selector Specificity
Type, pseudo-element selectors 1
Class, pseudo-class, attribute selectors 10
Id selector 100
inline style attributes 1000

The specificity is a sum of the specificity values, e.g.:

p::after                          //1(type)+1(pseudo-element) = 2
[type=email]                      //10(attrib. selector)      = 10
p.important                       //1(type)+10(class)         = 11     
aside.chart:first-child           //1 + 10 + 10               = 21

!important overrides the cascading properties. To be used if no better way, e.g., in case of an external CSS you cannot control.

Cascading order

  Origin Importance (the strongest last)
1 user agent (same as browser defaults) normal
2 user agent !important
3 user normal
4 author normal
5 CSS Animations (refer to links below)
6 author !important
7 user !important

In case of equal specificity, the latest declaration applies.

Caution needed not to override, e.g., font-families with comic-sans by !important, thus obsoleting the hard work of a CSS designer.

[This and the previous slide based heavily on MDN Specificity, and Cascading articles, do check them out.]

inherit

inherit-value in declarations means that the value is the same as it is in the parent element.

For example, border is not inherited but color is: when you want the text on a page to be blue one rule for the body suffices, whereas border for a list (<ul> element) does not influence its children. However, a property can be changed to be inherited. Notice that properties can have initial values (for color, it can be transparent)

inherit is an allowed value for every CSS property.

MDN inherit

important!

All the rules previously assigned to an element can be overridden by writing !important after a rule To be used in special situations only, for example visually impaired users may write a rule in the user style sheet (browser file userContent.css)

body { 
  font-size: large; !important 
}

Should not be used as a quick work-around, even if tempted to do so.

Box Model

Four edges

Box Model

Every element in an HTML document is represented as a box that has four edges: content edge, padding edge, border edge, and margin edge.

CSS - Box Model

In the box model, the children try to be as wide as the parent allows them to be...

...while the parent element aims for minimum height that fits all children

p.box_model_example {
    width: 20%;
    height: 20%;
    padding: 1%;
    margin: 2%;
    border: 5px;
}

Content, Padding, Border, Margin

Margins are always transparent. Horizontal margins don't overlap (collapse) while vertical (top and bottom) margins can collapse.

h2 { margin-bottom: 10px; }
p { margin-top: 5px;}
<h2>Collapsing Margins</h2>
<p>The margin between this paragraphs and
the heading above would be 10 pixels</p>

Padding is the area surrounding the content box that shares its background.

Border is between padding and margin and has: color, width, and style:

/* These two are equivalent */
h2 { border: 3px solid #FF0000; }
h2 { border-width: 3px; border-style: solid; border-color: #FF0000; }

Css

The positioning of the page

Normal flow

Without position or display declarations, the content flows from left to right, and from up to down. Elements are put laid out as densily as they fit by their default behaviour:

  • Inline elements go with the flow
  • Block elements assist in grouping the flow in separate sections
  • Elements are positioned static by default (z-index of zero)

position, z-index, float and display attributes distrupt the flow.

Inline & Block

Elements are divided into inline and block elements.

Inline elements, such as span and a, occupy only the space needed and flow "like text" from left to right without line breaks.

Block elements (such as div and p) inhabit the entire width of parent element (remember box model from couple slides ago?). Typically, there is a new line inserted before and after them. Height can be set more or less than the elements occupy; overflow is controlled with options

Elements can be changed from inline to block by display declarations.

/* Would insert line breaks before and
after links with the class menu_item */
a.menu_item { display: block; }

Position

The position of an element can be set with a position attribute

It can be set as:

  • static - The element is positioned as in normal flow
  • relative - Element is positioned relative to its "normal" position
  • absolute - Element is positioned relative to the nearest positioned ancestor or if there is no positioned ancestor to the container of the document
  • fixed - Element is positioned relative to the viewport. It has the effect of keeping the element in the same position in the window even when scrolling.
  • sticky - Mixture of relative and fixed positioning. Not yet widely supported.

accompanied with
top, bottom, left, right to tell the new location.

MDN on Position

Position Example

/* Will always stay at the top left corner of the viewport */
p.annoying_notice {
    position: fixed;
    top: 20px;
    left: 20px;
}
/* Will be 20 pixels lower and 20 pixels to
the right of where it would be without this style */
p.side_note {
    position: relative;
    top: 20px;
    left: 20px;
}

z-index

When location (x,y) is forced, elements may overlap

  • z-index comes to the rescue; elements can be layered
  • with equal z-indices, the latest is the foremost
  • static implies z-index zero, other positions z-index one
  • the greater the number, the nearer to the user the element is
  • z-index must be an integer and it can be also negative

Easier way to implement flexible layouts.

Elements are laid out within their parent: flex container. Its display is set as flex. Both horizontal and vertical directions are possible.

Width and height are not used. Instead, directions are main and cross axis. Direction is changed with flex-direction.

Grid

display: grid

Flexbox defines layouts in 1D, grid in 2D. Thus, CSS Grid is suited for the layout of entire web pages.

Grid layout definition:

<elem class="container">
  <!–- grid items --> 
</elem>
elem.container { 
  display: grid; 
  . . . 
}

Grid container contains grid items.

grid-template-rows and -columns

Similar features with flex positioning include:

  • main- and cross-axes
  • justify-content and align-items
  • stretching and shrinking items flexibly to fill the space as desired

Grid adds to this rows, columns and areas, that expand the control to 2D:

grid-template-rows: auto auto;      //two rows occupy space available
grid-template-columns: 1em 2em 3em; //three columns with given sizes

Together, rows and columns define a grid.

Responsiveness in grids with enablers

fr prompts responsiveness being flexible in nature, -I occupy space what is left and do not cause trouble by flowing over, , but fr alone does not do the trick, there are three more steps to take - the steps are:

  1. repeat()
  2. minmax()
  3. auto-fill/auto-fit

Pippa L. needed!

1. repeat()

First, let us be reminded of grid-template-columns. Column widths can be defined as follows: 
grid-template-columns: 1fr 1f 1fr 250px;

1fr tautology can be removed with:

repeat(3, 1fr)
.. altogether: 
grid-template-columns: repeat(3, 1fr) 250px;

The 1st parameter (3) is the multiplier - the 2nd, 1 fr, is the size.

Either or both of these parameters can be made more negotiable, more space-savvy.

2. minmax()

Let us start from the latter parameter of size, in this case 1fr. To make the size more adjustable, we can define a range for it by setting min- and max-widths. Let us define the range as a mix of absolute and fraction values: minmax(100px, 1fr). Thus, we have:


  grid-template-columns: repeat(3, minmax(100px, 1fr)) 250px;

The logic of minmax:

  • 1fr < 100px, then the width is min-width: 100px;
    minmax() attempts to guarantee a decent space for the content
  • 1fr > 100px, the width is 1fr

Based on the chosen strategy, elements overflow or wrap, and if space is very limited, also min-widths are compromised.

The last part (250px) adds to the "flexibility buffer". It takes what is left from 3 * minmax(), if space < the calculated width.

3. auto-fill/auto-fit

In lack of space, elements start to overflow. In the worst case, they are not visible anymore, nothing we desired.

To make a grid container truly responsive, the first repeat() parameter, a multiplier, must be "flexified" as well in addition to minmax() flexification. For the purpose we introduce the needed last step: auto-fill/auto-fit. 

grid-template-columns: repeat(auto-fill, minmax(100px, 1fr)) 250px;
versus 
grid-template-columns: repeat(auto-fit, minmax(100px, 1fr)) 250px;

In excess of space, auto-fill vs. -fit signifies

The difference becomes visible the clearest in the excess of space, for example, in case of minmax(100px, 1fr):

auto-fill: the min of 100px is used,

auto-fit: the max of 1fr is used instead.

Media queries

Media queries

for adapting to different devices with CSS3 media queries:

Media Query specification supports features grids are not capable of handling, such as pointer types, resolutions, aspect-ratios. Adaptation to display capabilities/user-preferences can be done in a fine-grained manner.

During this course, practice with grids and use media queries only as a complementing technique, where grids prove to be inadequate.

@-rules

@media in CSS defines how CSS styles behave in specified media-types or conditions.

@media belongs to so-called at-rules. at-rules may be conditional - like @media.

The rule is followed by media-queries, namely the conditions that specify when certain rules are to be applied. The query consists of either media-type (screen, paper, speech or all) or certain display sizes, e.g. (min-width: 900px). The queries are enclosed in parentheses and combined with and, or, not and special only.

Media query: media-features

width | min-width | max-width | height | min-height | max-height| aspect-ratio | color | resolution | orientation | scan ... 
@media (min-width: 768px)  { css-rule }
@media (min-width: 768px)  and (max-width: 991px) { css-rule }

Media query: media-type

all | aural | braille | handheld | print | projection | screen | tty | tv | embossed | speech ... 
@media (print)  { css-rule }
@media (min-width: 700px), handheld and (orientation: landscape)
{  css-rule  }

For more, check, e.g., the site W3Schools material

Typical media query

  • Basic style rules and special style rules for certain screen widths.
    • First we define the rules that apply regardless of the window width.
    • With media queries we change the basic style rules, or add new rules for certain situations.
p { 
    color: blue; 
}
/* Remember, non-overlapping widths!*/
@media (min-width: 1200px)  { 
        rules for wide screens only
}
@media (min-width: 992px) and (max-width: 1199px)  { 
    rules for laptop sized screens
}

Typical viewport widths

Small phone < 600px
Phone 600px - 767px
Tablet 768px - 991px
Desktop 992px - 1199px
Wide desktop >= 1200px

The same with media queries

  /* Extra small devices (phones, 600px and down) */
  @media only screen and (max-width: 600px) {...}
  
  /* Small devices (portrait tablets and large phones, 600px and up) */
  @media only screen and (min-width: 600px) {...}
  
  /* Medium devices (landscape tablets, 768px and up) */
  @media only screen and (min-width: 768px) {...}
  
  /* Large devices (laptops/desktops, 992px and up) */
  @media only screen and (min-width: 992px) {...}
  
  /* Extra large devices (large laptops and desktops, 1200px and up) */
  @media only screen and (min-width: 1200px) {...}

These five Typical Device Breakpoints are represented by W3Schools as a well-accepted de facto standard.

Accessibility

Standards and tools

Equity of opportunities

Accessibility is important for giving everyone equal opportunities to access information. Formal organizations are mandated to follow the accessibility instructions and deliver the information in such a manner that everyone can read it; a few countries have even written this right to their law. Moreover, accessible sites tend to rank higher on search engines and be more usable in overall.

W3C initiatives

Several specifications and projects target better accessibility for visually impaired people, such as Web Content Accessibility Guidelines, and WAI-ARIA of W3C. In addition, such open source projects as A11y Project have joined the effort by crowd-sourcing more material, e.g., writing accessibility articles, editing inaccuracies, and providing high-level information. For more information, see https://a11yproject.com/.

[A11y is the short form way of writing accessibility. It is known as a "numeronym", where 11 denotes the missing 11 letters between 'a' and 'y']

HTML Accessibility

  • Write HTML with accessibility in mind
  • Provide the usera good way to navigate and interact with your site: the main things should be easily accessible
  • Make your HTML code as semantic as possible, so that the code is easy to understand for visitors and screenreaders.
